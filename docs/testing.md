# 实操测试指南（人话实测，直击重点）

不要去纠结那些繁琐细碎的边角断言，如果你想验证当前的数据包转运工具是否稳定可靠，**只需要重点测试以下 5 项核心能力**：

---

## 重点一：Web 模式基础转换测试（无需启动酒馆，纯本地沙盒）

- **测试目的**：验证纯前端 Web 环境下的解包、四端格式互转、文件细粒度拆选、智能分卷是否能完整闭环。
- **实操步骤**：
  1. 启动 Web 模式：在项目根目录运行 `npm run dev`（系统固定且默认仅启动端口 **3040** 单一服务，开箱即用；端口 4173 仅用于静态打包预览），打开浏览器访问 `http://localhost:3040/`（或直接使用 [GitHub Pages 在线页面](https://jiozhaoyue.github.io/ST-pack-transfer/)）；
  2. 拖入或选择一个现成的酒馆数据包 ZIP（例如 SillyTavern 导出的备份包）；
  3. 查看左侧图表：检查角色卡、聊天记录、世界书等数量是否准确解析；
  4. 切换目标酒馆（例如选择 TauriTavern 或 Luker），并设置分卷阈值（如 100 MB）；
  5. 点击「生成导出包」，完成后在导出区点击「下载」；
  6. 解压下载的 ZIP 检查文件目录：Luker 必须包含 `manifest.json`，TauriTavern 必须全部落入 `data/default-user/` 下。

---

## 重点二：Dev 宿主实例实测（Dev Luker 与 TauriTavern 真实环境联动）

- **测试目的**：验证插件装入真实宿主后的注入挂载、从宿主直接拉取数据、写回恢复以及桌面环境下的连通性。
- **实操步骤**：
  - 在终端执行全自动错峰测试指令：
    ```bash
    node scripts/run-e2e-instances.cjs --only dev-luker,tt-cdp
    ```
  - **脚本自动执行以下全套动作，绝不需要在 UI 手动点更新**：
    1. 自动从 Git 远程仓库拉取最新提交更新 Dev Luker 宿主与插件克隆；
    2. 自动启动 Dev Luker（8003 端口），测试插件挂载、注入点与数据拉取，测完自动停机；
    3. 自动启动 TauriTavern 桌面 WebView2 运行时（CDP 9223 端口），测试扩展注入与功能识别，测完自动清理；
    4. 查看终端打印的汇总报告，确认 `dev-luker` 和 `tt-cdp` **全绿** 即代表真实宿主环境验证通过。

---

## 重点三：Luker ↔ TT 双向私有件留存测试（跨宿主往返零丢失）

- **测试目的**：验证各酒馆独有的私有配置文件（如 Luker 的 `stats.json`、`macros.json`、`secrets.json` 等）在互转时绝不丢失、绝不泄露到目标酒馆根目录。
- **实操步骤**：
  - 在终端执行针对性单元测试：
    ```bash
    npx vitest run test/luker-tt-bidirectional-retention.test.js
    ```
  - **核心检验点**：
    1. **Luker → TT**：Luker 私有件自动封箱到 `data/default-user/_compat/luker/` 下，既完整保留，又不污染 TT 顶层目录；
    2. **TT → Luker**：逆向转回 Luker 时，`_compat/` 下的私有件自动拆封还原回根目录 `stats.json`，字节与原件 100% 一致。

---

## 重点四：自动备份与定时裁剪测试（严格按用户偏好）

- **测试目的**：验证自动化备份产生多份历史快照后，系统是否严格按照用户设置的保留份数（retention）自动淘汰最旧版本，绝不多占配额。
- **实操步骤**：
  - 在终端执行快照修剪测试：
    ```bash
    npx vitest run test/transfer-prune.test.js
    ```
  - **核心检验点**：
    - 模拟生成 5 份历史备份快照，用户设置保留份数 `keep: 3`；
    - 系统必须精准裁剪删除最旧的 2 份，完整保留最新的 3 份，绝不擅自多占用户云端或本地存储空间。

---

## 重点五：扩展安装健壮性测试（强制更新与脏 commit 自愈）

- **测试目的**：验证当扩展目录存在本地脏改动、分支偏离或残留锁定时，扩展安装引擎不会像普通宿主那样无脑报错或甩锅给“网络错误”，而是能自愈覆盖或清空重装。
- **实操步骤**：
  1. 在酒馆已装扩展目录中随意修改某个文件，或者制造一个本地提交；
  2. 打开「扩展管理」，再次粘贴该扩展的 Git 仓库地址并点击安装；
  3. **检验结果**：观察插件是否能自动检测冲突、执行强制重置或重新拉取覆盖，100% 成功完成安装与版本切换，无任何红字报错。
