# 存储引擎互转（Luker 专属）

Luker 支持将用户数据存储在多种底层引擎中（包括普通文件系统、PostgreSQL、MySQL 和 SQLite）。本功能让你在这些存储引擎之间自由互转，省去手动搭建和配置临时数据库的繁琐操作。

## 功能介绍

当你在顶部目标平台选择 **Luker** 时，左侧图表面板会贴心展示「存储引擎」选项。**在 Luker 宿主里选中数据包后，目标引擎会自动切换到该宿主包声明的源引擎**（文件系统 / PostgreSQL / MySQL / SQLite），不需要你每次手动重选：

- **跟随源包**：保持原始数据包的存储形态；
- **文件系统**：转为通用的普通文件目录格式；
- **PostgreSQL**：转为 PostgreSQL 适用的数据库转储包；
- **MySQL**：转为 MySQL 适用的数据库转储包；
- **SQLite**：转为 SQLite 适用的单文件数据库包。

选择对应的存储形态即可直接生成对应的数据包：

- 转换为**文件系统**后，可以直接在酒馆中按常规流程导入恢复，无需提前启动数据库服务；
- 转换为数据库形态后，会生成对应引擎的标准转储与元数据，导入时同样直接顺畅。

## 多种存储形态任意互转

支持在文件系统与各类数据库引擎之间双向互转，同时也支持 PostgreSQL 与 MySQL 之间的数据库同构迁移。

## 包内引擎载体（bin）是否必须

- **文件系统源包**没有 `_engine_meta.json` / `_engine_dump.bin`；文件系统转数据库时**不需要** bin。
- **PostgreSQL / MySQL 源包**必须同时保留 `_engine_meta.json` 与 `_engine_dump.bin`。缺少 dump 时转换会在开始前直接失败并说明原因，不会产出半成品。
- **SQLite 源包**保留单文件 `luker-storage.sqlite`，不使用 `_engine_dump.bin`。
- **数据库转文件系统**必须先有 dump（或 SQLite 数据库文件）才能还原；只保留零散文件不算完整备份。
- **目标为数据库**时，插件会写出对应引擎的 `_engine_meta.json` 与转储（SQLite 写出 `luker-storage.sqlite`）。

### 快而稳的做法

- 文件系统 → 文件系统：直接搬运目录，不经过数据库模型。
- 文件系统 → 数据库：走统一行模型 + 目标引擎 sink，逐表写入。
- 数据库 → 文件系统：先校验 `_engine_meta.json` 与 dump 完整性，再按表重建文件。
- PostgreSQL ↔ MySQL：走同一套 canonical 行模型，不经过中间 SQL 文本。
- SQLite 只在需要时加载 sql.js，避免为纯文件转换付出初始化成本。
- 大包优先流式处理，避免把整包读入内存。

## 跨酒馆平滑迁移

如果将 Luker 的数据库形态数据包迁移到 SillyTavern、TauriTavern 或 PureTavern 等以普通文件为主的酒馆时，插件会自动将数据库记录解析并还原为标准的用户文件结构，确保角色卡、个性化配置与聊天记录完整保留。

## 本地隐私与安全性

- **全流程本地解析**：数据解包、转换与打包全程在浏览器本地进行，既不会将你的聊天数据上传到外网，也不需要连接任何外部数据库，保障隐私安全；
- **格式校验明确**：遇到未知或损坏的源文件时，会及时在日志中给出清晰的错误提示，方便你核对源包完整性。
