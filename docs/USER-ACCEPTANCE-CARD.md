# 真人验收目标卡（S6）

> 用途：`10-01` 的 S6 要求**用户本人**在**无 AI 指导、无操作脚本**的前提下完成一次跨宿主迁移，
> 并记录卡点。本卡**只写目标与判据，不写步骤**——步骤本身就是被检验的对象。
>
> 记录方式：把卡点直接写进本文件末尾的「卡点记录」节，或另开一处；不必整理成文，原样记下即可。

## 一、目标（一句话）

把一份**真实的**数据包从 A 宿主搬到 B 宿主，并在 B 宿主里**确认数据可用**。

- A / B 任选（建议用两个 **Dev** 实例，例如 Dev ST ↔ Dev Luker；**不要**用 Real 实例）。
- 用你自己真实或半真实的数据，**不要**只喂合成小样本——数据量本身就是被检验的一部分。

## 二、成功判据（只看可观察结果，不看"测试是否通过"）

1. **范围说得清**：迁移结束后，你能自己说清「这次搬了哪些类目、哪些没搬、为什么没搬」。
   如果说不清，说明界面对范围的呈现不合格——**记下来**。
2. **两种产物分得清**：你能分清手里哪一份是**保底文件**（原样备份，出事时能退回去）、
   哪一份是**要导入目标宿主的目标包**。分不清就是命名/呈现不合格——**记下来**。
3. **目标侧真的能用**：在 B 宿主里至少能看到你勾选范围内的**角色卡**、**聊天记录**、**世界书**。
   打开一条聊天、点开一张角色卡，确认不是空壳。
4. **没有"卡住"的时刻**：全程**任何一步**你出现「不知道下一步该点哪 / 该选什么 / 这个选项什么意思」
   的犹豫，就是一个卡点。

## 三、卡点怎么记

每个卡点记三件事，一句话一条即可：

| 在哪一步 | 你当时的预期 | 界面实际给了什么 |
| --- | --- | --- |
| 例：选完源包之后 | 以为会自动开始转换 | 停在「范围」页，没说还要做什么 |

**不要**在卡点里写「应该加个提示」这类方案——先只记**现象**，方案由我这边来提。

## 四、明确不要做的事

- **不要**让我在旁边指路或解释界面——那正是本关要测的东西，指了就白测。
- **不要**为了"让它跑通"而绕过界面（例如手工改包、手工拷文件）——绕过的每一步都请如实记下
  「我因为 X 绕过了 Y」。
- **不要**在 Real 实例上做（`8002` / `8004` 是真实数据区，不可逆）。
