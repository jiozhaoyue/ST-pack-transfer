# Luker 2.8.0「账户设置 · 同步」对照表

> 来源：`D:\Repo\Tavern-repo\Instance\Dev\Luker\docs\improvements\{sync,lan-sync,s3-sync}.md`（Luker 2.8.0 Dev 实例文档）。
> 用途：P2-2 的第一项交付物——**Luker 区块 → 本项目落点 → 差异理由**。
> 约束：只照抄**信息层级与交互**，不复制宿主品牌、代码与端点（见 `host-capabilities.md` §「四宿主原生局域网同步」）。

## 1. 入口与信息架构

| Luker 2.8.0 区块 | 本项目落点 | 差异理由 |
| --- | --- | --- |
| User Settings → Account → Backup & Restore → Sync → Open Sync | 工作台「局域网互传」按钮（已存在）→ 整面板替换图表区（`workbench-single-view.md` §7.3） | 本项目是**一次性搬运**，不是常驻同步引擎；入口放工作台而非设置，减少层级 |
| Sync backends 列表（label / LAN·S3 / 上次同步 / 错误 / Sync now / Undo / Edit / Remove / Unlock） | 传输会话列表：目标设备名 / 方式（近场 WebRTC · 云端仓库）/ 时间 / 状态 / 重试 / 取消 | 没有「长期后端」概念，只有一次传输会话；「Undo/Edit/Unlock」无对应语义 |
| This device's label + Save device label | 发送端昵称（用于取件码/对比确认） | 仅用于识别，不参与版本溯源 |
| Sync schedule（60s / 300s） | **不实现** | 无后台常驻；搬运由用户显式触发 |
| 自动同步触发（启动 / 空闲 / 轮询 / 对端通知） | **不实现** | 同上；不引入定时器与后台轮询 |

## 2. 类别与敏感数据

| Luker 2.8.0 | 本项目落点 | 差异理由 |
| --- | --- | --- |
| 类别多选（Characters / Chats / Worlds / Presets / Themes / Assets / Settings…；Secrets、Extensions 为 opt-in） | 现有 10 类目 + 3 特殊类目的勾选树（`inspect.js`） | 类目口径本就对齐 ST 用户目录 |
| Secrets 默认关 | 私有配置（`_private/`）默认随规则保留，但**传云**需显式操作 | 我们的私有件是显式 artifact，不是宿主凭据 |
| 缩略图 / 缓存 / 自动备份 / 迁移归档 / 运行日志不同步 | 类目树里「派生缓存」「备份快照」默认不勾 | 已有同类默认值（`P0-3`、备份聊天过滤） |

## 3. 冲突、撤销与恢复

| Luker 2.8.0 | 本项目落点 | 差异理由 |
| --- | --- | --- |
| 待决冲突（版本卡 / In use / Current version / Apply choices） | 覆盖 / 增量两种导出语义（`delta.js`） | 搬运给出的是**产物选择**，不是双端合并；无常驻历史可比 |
| 聊天分支与恢复通知 | **不实现** | 属于宿主运行期能力，插件不改写聊天 |
| Undo last sync | 导出队列可重新生成（源包仍在本地库） | 没有「已推送到对端」的撤销语义 |
| 读/写错误明细表 | toast + 审计日志（`#view-log`） | 同等信息，落点不同 |

## 4. 传输与安全

| Luker 2.8.0 | 本项目落点 | 差异理由 |
| --- | --- | --- |
| LAN：配对链接（一次性 10 分钟）/ 反向可达检查 / Basic auth | 近场传输：取件码 / 应答码 / 扫码 / 64KB 分块 / SHA-256 / `.part` 续传（已实现） | 无账号体系，用一次性码替代配对链接；不依赖宿主反向可达 |
| LAN 无 TLS 时明文提示 | 面板内明文风险提示 | 同口径 |
| S3：endpoint / region / bucket / prefix / path-style / ETag 引号 / 凭据 / 加密短语 | **待裁定**（见下节） | 需要后端参与签名与加密，不能纯前端直连暴露长期凭据 |
| 私有地址策略（管理员） | 不适用（单用户工具） | 无多用户/管理员概念 |
| 存储模式（file / SQLite / MySQL / PG） | 不适用 | 插件不承载宿主数据库 |

## 5. 与既有产品边界的冲突（必须先裁定）

`host-capabilities.md` §「四宿主原生局域网同步」（2026-10-27 取证）写明：

- 原生局域网同步是**宿主自身能力**（同宿主设备之间），**插件不显示、不触发、不代理**；
- **不专门造公网 P2P**；现有局域网 WebRTC 行为**不删不扩**。

P2-2 要求的「把局域网、S3 等能力化为本项目功能」与之存在两点张力：

1. **Luker 原生 LAN Sync 不能接**：`/api/sync/v1/*` 属宿主端点，插件调用即违反上述边界与 `L0-12`。
2. **「不扩」限制**：把现有一次性近场传输改造成「同步后端 + 计划 + 冲突版本卡」属于扩张，
   且与「搬运工具」的定位不符。

## 6. 可选落点（供裁定）

| 方案 | 内容 | 代价 | 与本项目定位 |
| --- | --- | --- | --- |
| A 只做信息层级对齐 | 现有局域网面板按 Luker 的分组重排：设备 / 类别 / 传输 / 结果，不加后端与计划 | 小 | 一致 |
| B A + 云端包仓库（S3 兼容） | 新增「包仓库」：把导出包上传/下载；凭据存本地，直连或经 Authority 代理 | 中（签名、CORS、加密） | 一致（仍是包搬运） |
| C 完整同步引擎 | 后端列表 + 计划 + 冲突版本卡 + 撤销 | 大 | 与「不扩」冲突，不建议 |

> **2026-11-05 用户裁定：选 A+B**。已落地：末节对照（A）中的信息层级（`#lan-overview`）+ 云端包仓库（B，
> `src/core/s3-client.js` / `s3-crypto.js` / `#cloud-view`）。C 不做。

> 无论选哪个，都遵守 `L0-11`：纯前端主路径可用，后端不可用时静默降级、如实显示「未提供」。
