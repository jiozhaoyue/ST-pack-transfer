### R5 S3 存储通用化（按本插件操作逻辑重做）

- 目标：不再「一次 PUT 整个 zip」，接入本插件核心语义：分包、增量、断点、勾选、进度、暂停/继续。
- 判据：
  1. 大包按固定分片（默认 8 MB）上传；中断后重传只补缺失分片（服务端已有分片 HEAD 命中即跳过）。
  2. 同内容再次上传：全部分片命中 → 零字节上传，状态显示「已存在」。
  3. 下载支持 Range 分片 + 断点，最终 sha256 与上传清单一致。
  4. 所有失败显式分类：网络 / 认证 / 权限 / 不存在 / 服务端错误；不吞异常、不假成功。
  5. 单测以注入 `fetch` 覆盖：正常、跳过、断点、校验失败、重试。

### R6 WebDAV 支持（极其健壮，永远不 405）

- 目标：新增 `src/core/webdav-client.js`，所有请求可探测、可降级、可重试；
  任何单一方法被禁都不导致整体失败。
- 判据：
  1. `OPTIONS` 读 `Allow`；`PROPFIND` 405/501 → 降级读 `manifest.json`；
     `MKCOL` 405/409 → 视为目录已存在；`PUT` 405 → 报告「服务器禁止写入」并给出可用方法清单。
  2. **不使用** PATCH / LOCK / MOVE 作为主路径；所有主路径只依赖 GET / PUT / HEAD / DELETE。
  3. 分片上传：`<name>.partNNN` → `manifest.json` 最后写；下载按 manifest 合并并校验 sha256。
  4. 断点：本地记录已完成分片；中断后只补缺失分片。
  5. 认证：Basic 优先；401 且带 `WWW-Authenticate: Digest` 时如实提示「需服务端代理」。
  6. CORS 失败（TypeError: Failed to fetch）单独分类，提示改用服务端代理或配置 CORS。
  7. 单测覆盖：405 各分支、401、409、Range、断点、manifest 缺失/损坏。

### R7 自动同步（服务端 → WebDAV，不经过本机）

- 目标：用户点一次，服务端把指定数据直接推到 WebDAV，浏览器不承载字节。
- 前置：服务端执行体（见 §2 待裁定）。
- 判据：
  1. 触发期间浏览器网络面板**零**大文件上传流量（仅状态轮询）。
  2. 服务端日志/回执可查：源、目标、分片数、校验结果。
  3. 服务端不可用 → 入口显示「当前宿主不支持服务端直传」，不隐藏原因、不假成功。
  4. 可选「失败回退本机中转」，默认关闭。

### R8 通用化：所有酒馆可用

- 目标：Luker 专属能力全部走**能力声明表 + 特性检测**，其它宿主显示「当前宿主没有」。
- 判据：
  1. 新增 `HOST_STORAGE_PAGE` / `HOST_ACCOUNT_WINDOW` / `HOST_SERVER_TRANSFER` 三张显式声明表，
     值只描述能力，不推导平台名。
  2. ST / TT / PT 上：注入按钮按各自既有锚点工作；配额行点击提示「当前宿主未提供存储页面」；
     自动同步显示不支持。
  3. 独立 Web 态：全部入口隐藏或给出「无宿主」原因，主路径（本地转换 / 局域网）不受影响。

## 2. 裁定结果与能力分析（2026-11-09 用户裁定）

### 2.1 已确认的宿主能力边界（取证）

| 能力 | Luker 2.9 | ST | TT | PT |
| --- | --- | --- | --- | --- |
| 服务端插件（Node，可读文件/长任务/注册路由） | **有**（`plugins/`，`enableServerPlugins: true`，路由挂 `/api/plugins/{id}/`，继承鉴权） | 无 | 无（扩展不能 invoke Tauri 命令） | 无插件机制 |
| CORS 代理端点 | 有 `/proxy/:url(*)`（`enableCorsProxy`，**默认关**） | 有同类（`enableCorsProxy`，默认关） | 无 | 无 |
| 代理的 body 限制 | `JSON.stringify(req.body)` ⇒ **二进制/ZIP 不可经此代理** | 同 | — | — |

⇒ **结论**：
- **真·零本机流量**只有「Luker 服务端插件」能做到（服务端读数据 → 服务端直传 WebDAV）。
- 其余宿主只能「流式转发」：宿主备份响应 → 浏览器 ReadableStream → 逐块上传。**不落盘、不整包入内存**，
  但字节仍经本机网卡。UI 必须如实写「经本机网络」，不得宣称省网卡流量。
- 原生 `/proxy/` 只承担小请求（鉴权探测、OPTIONS、PROPFIND 小 XML 也需实测）；大包分片一律直连或服务端代理。

### 2.2 自动备份（R7 重定义）

自动备份是**独立设置域**，与图表勾选不是同一份偏好，UI 必须常驻提示：

> 「这里的偏好只作用于自动备份，不会改变图表里的勾选。」

模式（单选）：

| 模式 | 数据路径 | 可用宿主 |
| --- | --- | --- |
| `stream-direct` | 宿主备份响应 → 逐块直传 WebDAV/S3，**不落盘、不整包入内存** | 全部宿主（标注经本机网络） |
| `pull-trim-upload` | 宿主拉取 → 插件按**自动备份偏好**修剪 → 上传 | 全部宿主 |
| ~~`server-direct`~~ | 服务端生成 → 服务端直传 | **本插件不做**（2026-11-09 用户明令禁止后端插件）；可行方案登记在 [`docs/FUTURE-BACKEND-CAPABILITIES.md`](./FUTURE-BACKEND-CAPABILITIES.md)，供基石插件改造 |

所有模式启动前必须弹出**流量提醒**（预计字节；未知则如实写「未知」），并列出「数据将离开本机」的
目标与协议。所有手工上传/下载/自动同步入口同样适用。

### 2.3 WebDAV 路径（D-2 裁定）

直连为主 + 插件内可设置代理；代理按能力表降级：

| 代理策略 | 实现 | 适用 |
| --- | --- | --- |
| `direct`（默认） | 浏览器 fetch 直连 | 全部 |
| `host-proxy` | ST/Luker `/proxy/` 前缀转发 | 仅小请求；二进制自动判定为不可用并降级 |
| `custom-proxy` | 用户填写的 HTTP 代理基址，插件拼 `?url=` | 需代理本身允许 CORS |
| `server-plugin` | Luker 服务端插件通用转发 | Luker 且插件可用 |

代理选择不写死平台名：`probeTransferProxy()` 逐项探测「可用 / 不可用 / 原因」，
不可用项显示原因而不是静默消失。
