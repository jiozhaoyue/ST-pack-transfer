# 计划 · 2026-11-10 工作台交互与云端上传重构

> 用户当轮指令 + 四个已确认口径。**执行中实时更新状态**，不凭记忆补记。
> 口径：① 图表最大化逐层下钻；② 图表占比动态跟随勾选；③ 设置清空全部包记录；
> ④ 清单包展示 + 可编辑来源 URL（不做“必须自建 HTTP 服务”的强制前置）。

## 一、目标

1. 数据包列表取消固定顶部按钮，动作只在勾选后出现在列表下方；导出区同样如此，删除卡后三按钮。
2. 「合并上传」删除；「回传宿主」改名「上传」，全界面只保留一个「上传」概念。
3. 「从宿主拉取」「迁移与备份」「导出扩展清单」移到插件顶部全局动作条。
4. 图表最大化改为 Luker 式逐层下钻（一次一层，面包屑返回）。
5. 图表占用占比按当前勾选动态计算。
6. 修复“聊天记录莫名取消勾选”。
7. 设置新增「每次加载清空浏览器存储（暂存数据包）」，默认不勾选；清空全部包记录，保留设置/偏好/日志。
8. PT 目标产物不得再显示成 TT；PT 与 TT 分组分离；帮助中说明 TT/PT 兼容边界。
9. 问号帮助补全：四酒馆数据包规则（与 README 同步）、勾选语义、扩展清单/资产列表全套教程、TT/PT 警告。
10. 仅清单包导入后可在插件内看到清单，并可填写 http(s) 来源 URL 安装；说明无需为本插件自建 JSON 服务。
11. 云酒馆上传改用 Luker 原生 8MiB 分片恢复协议；无分片端点时回退整包 POST。
12. 分卷保留但降级为可选（对象存储/本地导入限制），帮助中如实说明其原始 100MB 动机已由分片上传解决。

## 二、验收判据

- 导入区未勾选时列表下方无动作按钮；勾选后出现「生成导出包」等，无「合并上传」。
- 导出区勾选后出现「下载 / 上传 / 复制回导入区 / 删除」；卡片上无任何按钮。
- 顶部全局动作条含「从宿主拉取 / 导出扩展清单 / 迁移与备份」。
- 最大化图表只显示一层；点分类进入下一层；面包屑可返回；不再同屏展开整棵树。
- 取消勾选一个类目后，图形对应色块消失、其余占比按勾选重算。
- 连续操作（拉取、切换包、切换区、重渲染）后聊天记录勾选保持用户选择。
- 设置开关默认关；打开后下次加载包记录为空，设置/偏好/日志仍在。
- 目标 PT 的产物在导出区显示 PT 徽标/分组，不显示 TT。
- 帮助问号内包含四平台规则、勾选、清单、资产列表、TT/PT 警告，可滚动阅读。
- 仅清单包可在插件内列出扩展条目与 URL 状态；缺 URL 可填 http(s) 并尝试安装。
- 云酒馆 >100MB 包恢复走 `POST /api/users/restore-backup/uploads` → 8MiB `PUT` 分片 → `finalize` → `POST /api/users/restore-backup`；日志可见分片进度。
- `npm test` 目标文件 + 五个 UI 守卫 + `check:i18n` + `check:copy` 通过。

## 五、证据与备注

- 云酒馆根因：CF 代理单请求体上限 100MB（`.trellis/spec/ops/tunnel-and-keepalive.md` §6）；
  Luker 原生分片 `RESTORE_UPLOAD_BASE_URL=/api/users/restore-backup/uploads`、`8MiB`、
  413 减半、3 次重试（`Instance/Dev/Luker/public/scripts/luker-chunked-upload.js`）。
- ST 1.19.0 无整包恢复端点（`grep restore-backup` 无命中），故分片仅对有后端的 Luker 生效；
  其它宿主保持候选探测 + 整包回退。
- 清单 JSON 与本插件安装路径：`_convert/extensions-manifest.json` 由插件从 zip 内读取后调用宿主
  `/api/extensions/install`；不需要托管 JSON。官方资产列表 JSON 才是宿主 Asset URL 菜单的输入，
  如需用原生菜单才需要本地/局域网/服务器 URL。
