# 问题报告

遇到问题需要反馈时，用「问题报告」一键采集环境信息并生成脱敏报告。
报告可复制到剪贴板、导出为本地 Markdown，也可直接提交到 GitHub Issue。

默认不采集聊天内容、角色卡、世界书与宿主用户名。
所有对外文本统一经过脱敏层，凭据不会随报告外泄。

## 一、打开入口

在工作台打开「设置」视图。
展开「问题报告」分组即可看到完整表单。

> 面板打开时会调用 GitHub API 反查仓库坐标并拉取 Issue 模板，失败会静默降级，不影响使用。无需填写仓库地址，平台与账号在下拉中直接选择。

## 二、填写表单

按模板字段逐项填写。字段跟随 GitHub Issue 模板动态生成，不同仓库可能略有差异。

- **问题标题**：一句话概括问题。必填。
- **问题描述**：出了什么问题。
- **复现步骤**：如何重现。
- **平台**：当前仅 GitHub。
- **账号**：显示本机是否已配置令牌。显示「未配置」时，先到开发者设置添加令牌。
- **GitHub 令牌**：使用 fine-grained PAT，需目标仓库 Issues 读写权限。只存本机浏览器，不写入服务端。

如需提交到某个仓库，确认仓库所有者与仓库名已解析正确。
本仓与上游两条线的议题列表与文档在面板底部提供快捷跳转。

## 三、选择日志级别与条数

勾选「附带脱敏日志」后，可自选随报告附带的日志级别与条数。

级别按「不低于」过滤，共五档：

- 全部
- 信息以上
- 警告以上
- 仅错误
- 含调试

条数可选 50、100、200、500 或全部。

默认取最小安全档：级别为「警告以上」，条数为 100。
附带日志时会明确告知所采集的内容。
「含调试」档包含更多细节，日志同样会自动脱敏。
选择后，面板会实时显示「附带 N 条已脱敏日志」。

## 四、预览与渲染切换

提交前先点「预览报告」查看全文。
预览窗口提供两个视图：

- **原文**：Markdown 原始文本。
- **预览**：渲染后的视图。

两个视图可随时切换，确认内容无误后再提交。

## 五、提交前确认

提交到公开 Issue 前，必须完成两项前置勾选：

- 已读文档
- 已搜无重

未勾选时提交按钮不可用，界面会提示还需勾选的项目。
这一步用于避免重复提问与未读文档就提交。

## 六、三种出口

- **提交**：先经确认弹窗，再提交到 GitHub。弹窗明确提示公开 Issue 不可删除、可能被搜索引擎收录。提交成功会返回 Issue 链接。
- **复制全文**：将报告复制到剪贴板，可自行粘贴到任意渠道。
- **导出 Markdown**：导出为本地 `issue-report.md` 文件。

## 七、URL 护栏「内容过长 请复制」

通过 GitHub 网页新建 Issue 时，表单内容会拼进网址。
GitHub 对新建 Issue 的完整网址有长度上限。

当内容超过上限，提交不会静默失败，而是提示「内容过长 请复制」。
此时请改用「复制全文」或「导出 Markdown」，再手动粘贴到 Issue 正文。

也可配置令牌后走 API 提交，避开网址长度限制。

## 八、凭据与隐私

- 令牌使用 fine-grained PAT，权限只勾目标仓库的 Issues 读写。
- 令牌只存本机浏览器 `localStorage`，不写入酒馆 `settings.json`。
- 报告正文中的标题、描述、环境值与日志都会经过统一脱敏。
- 默认不含聊天、角色卡、世界书与宿主用户名。
- 公开 Issue 不可撤回，可能被搜索引擎收录。涉密问题请走私密渠道，不要提交公开 Issue。
