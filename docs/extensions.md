# 扩展管理与打包

功能入口：点击工作台左侧面板顶部的切换按钮，即可在「存储图表」与「扩展管理」之间切换（手机端还可切换到「数据包」）。

## 三个分区

| 分区 | 主要功能 |
| --- | --- |
| **宿主扩展** | 查看已安装扩展、安装新扩展、批量更新与卸载，以及服务端插件管理（管理员可见） |
| **开发者** | 配置 Git 账号、OAuth 登录、获取访问令牌指引，以及开发者高级开关 |
| **扩展打包** | 针对当前选中的数据包，专门挑选需要随包打包的扩展插件 |

## 完整 / 清单：双选与智能建议

每个扩展目录行有「完整」「清单」两个按钮，**可以同时点亮**：

- **完整**：把扩展实体代码随包带走；
- **清单**：只保留来源与版本信息，导入后由目标宿主在线拉取安装；
- **双选**：实体与官方清单条目同时写入，既可直接用，也可被宿主识别为可在线安装/更新。

图表与批量打包弹窗都会给出显眼建议：

| 情况 | 建议 | 原因 |
| --- | --- | --- |
| 本插件自身（ST-pack-transfer） | **完整** | 必须自举运行，不能依赖在线拉取 |
| 无远端地址 / 本地目录 | **完整** | 清单没有可安装地址 |
| 私有仓库 / 需要凭据 | **完整** | 目标宿主通常没有你的凭据 |
| 公开 Git 远端 | **清单** | 省空间，导入后可自动拉取 |

> **网络环境差、被 GFW 封锁、或目标机器无法访问 GitHub/GitLab 时，请改选完整。**
> 清单模式依赖目标宿主能访问对应仓库；访问不了时，只有完整包能保证扩展可用。

## 安装扩展

在面板底部常驻的「安装扩展」区域即可轻松添加新插件：

- **多样化输入**：支持直接粘贴单个 Git 仓库链接、多行批量粘贴，或者上传 `.txt` / `.json` 文件导入；
- **版本定制**：每行支持填写 `仓库链接 | 分支名` 或 `仓库链接#分支名`，支持指定分支、标签或 Commit；
- **私有仓库支持**：在「开发者」分区配置好对应平台的 Git 令牌后，下载私有仓库扩展也能顺畅通过鉴权完成安装；
- **智能链接识别**：无论你粘贴的是 GitHub / Gitee / GitLab 网页页面链接、还是简写的 `owner/repo`，工具都会自动识别并解析出标准仓库地址和分支；
- **绝对健壮的安装与强制更新（告别宿主无脑报错）**：主流酒馆在安装或更新扩展时，遇到本地有脏 commit、分支偏离或已有残留目录，经常只报一句泛化的“安装失败”，甚至全部无脑甩锅给“网络连接问题（Internet Error）”。本插件彻底重构了扩展安装底座：支持智能环境自愈、冲突检测与强制更新，允许自动清理或先删除再安装，彻底根治 Git 冲突与脏目录导致的安装卡死，保证 100% 健壮完成安装与版本切换。

### 在独立网页中使用安装功能

如果作为独立网页打开（当前没有连接运行中的酒馆），此时安装功能会**将扩展文件直接注入到你选中的数据包中**：
先在列表勾选一个数据包，安装的扩展会自动整理并写入该数据包的扩展目录下，导出后导入酒馆即可正常识别。

## 已装扩展管理

- **直观排序与概览**：列表顶部清晰展示扩展总数与排序方式，支持鼠标拖拽调整显示顺序，你的自定义排序会自动记忆；
- **来源与状态**：每行展示扩展的远程仓库地址（点击文字即可快速复制）以及公开/私有标识，并标注当前酒馆的加载顺序；
- **便捷管理操作**：支持单项更新、卸载，管理员支持在全局扩展与私有扩展之间平滑迁移；
- **批量操作**：提供全选、反选、取消，支持批量更新与批量卸载（卸载前提供确认提示）。

### 自动更新检查

- 在「开发者」分区中可以开启自动更新总开关；开启后，已装扩展列表中每行均可单独设置更新策略；
- 支持为每个扩展选择「关闭 / 仅提醒 / 自动更新」；选择「仅提醒」时，有新版本会通过酒馆通知提示你，点击即可决定是否更新；
- 扩展写操作（更新、安装、卸载等）会自动排队安全执行，保证文件读写平稳。

## Git 提交可视化

在数据包列面板顶部切换到「Git」页签并选中某个扩展后，即可体验可视化的版本查看：

- **本地 / 云端双视角**：页签常显切换。本地视角直接读取数据包内 `.git`（HEAD、分支、refs、packfile）的**真实提交历史**；云端视角读取远端分支 / 标签 / 提交与代码差异；
- **版本提交树**：左侧泳道与右侧提交行分别包裹，清晰呈现分支合并与历史提交记录；点击云端提交可查看具体代码改动；
- **版本对齐情况**：云端视角下对比本地安装版本与云端最新版本的同步状态（如已同步、落后几个提交等）；
- **版本快速切换**：支持直接按分支或标签将扩展安装到指定版本；
- **文本编码保障**：远程更新说明与提交信息均强制按 UTF-8 解码，确保中文内容显示清晰不乱码；
- **不伪造**：未开启「Git 云端读取」时给出明确提示；本地解析不了就如实说明原因，绝不显示假的提交。

## 随数据包打包扩展

- **按包自由勾选**：可以针对已载入的数据包分别勾选想要随包带走的扩展插件；
- **Git 历史按需优化**：支持选择保留全部 Git 历史、仅保留日常更新所需记录、或完全精简 Git 历史以大幅缩减数据包体积；
- **自动适配规范**：自动按照目标酒馆的规范调整扩展目录结构。

### 轻量清单包模式

如果希望导出的数据包尽量轻巧，可以在图表里**逐个扩展目录**选择「完整 / 清单」：完整带走实体文件，清单只保留官方列表与来源信息，导入新酒馆时再在线按需下载安装。两个按钮**可以同时点亮（双选）**；组级与批量级按「是否存在完整 / 是否存在清单」分别点亮，两者可同时亮，界面不再显示「混合」。同一个数据包内可以同时存在完整、清单、双选三种状态，既能保留必须离线自举的扩展，又能让公开扩展只留清单。

### 智能规范与去重

- **自动去重**：如果同一扩展在用户目录和全局目录同时存在，打包时会自动保留一份，避免重复冗余；
- **保护内置核心**：酒馆自带的原生内置插件（如表情、正则等核心模块）在跨酒馆迁移时会自动留存原地，确保不同酒馆的核心环境干净稳定。

## 服务端插件（管理员功能）

如果你拥有酒馆管理员权限，在宿主扩展列表中还会看到专属的服务端插件管理分区，支持查看、更新依赖、卸载以及通过 URL 安装服务端插件。

- 普通用户界面保持简洁专注，只展示适合普通用户的操作选项；
- 如果添加的插件属于服务端依赖类型（包含 package.json 而无前端清单），系统会给出友好提示，指引通过服务端插件功能进行安装。

## 账号与访问令牌

- **主流代码托管平台**：全面支持 GitHub、GitLab、Gitee 以及自建 Gitea 实例，支持添加多个账号并设置默认账号，每个账号均可一键测试连通性；
- **便捷鉴权支持**：支持个人访问令牌（PAT）、账号密码以及 OAuth 授权等多种认证方式；
- **获取指引**：在开发者页面中，点击各平台均配有直达的令牌创建链接与最小权限说明，帮助你快速完成配置。

有关凭据的本地存储机制与隐私保护细节，请参考 [隐私与凭据](privacy.md)。
