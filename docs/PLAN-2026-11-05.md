## 2. P0 · 数据正确性（最高优先）

### P0-1 浏览器 / 宿主配额读数始终 0/10，且不随数据变化

- **现象**：Luker 原生显示 `1.9 GiB / 11.9 GiB`；插件始终 `0 / 10`（或不变）。
- **目标**：插件读数与宿主原生同源、同量级；数据变化后实时刷新。
- **判据**：
  1. 同一时刻 Luker 原生与插件读数差 ≤ 1%（允许不同取整）。
  2. 新增/删除源包后 2 秒内读数变化。
  3. 宿主读不到时显示「宿主未提供存储读数」，不得显示假 0。
- **先读文档**：`docs/DEVELOPER-GUIDE.md` §I、`.trellis/spec/frontend/host-capabilities.md` §5（storage-inspector）、`state-management.md`。
- **涉及模块（文档级）**：`src/ui/usage-dashboard.js`、`src/ui/host-bridge.js` 的 `readHostStorageQuota()`、图表面板配额区。
- **依赖**：无。
- **状态**：DONE（代码，2026-11-05）——读数改为启动 + 每次 `syncPackages` + 15s 兜底 + 页面可见时刷新；Luker 读数增加宿主模块失败后的 `/api/users/storage/inspect` 同源兜底。**待 Luker 真机核对 1.9/11.9 量级。**
  > 注：`src/ui/usage-dashboard.js` 文档登记已过时，实际配额渲染在 `workbench-view.js` 的 `renderQuota()`；文档稍后修正。

### P0-2 拉取整包体积与类目体积对不上（1.9 GB vs 备份快照 2.5 GB）

- **现象**：拉取整包显示 1.9 GB，但类目「备份快照」显示 2.5 GB；且拉取前已从文件系统删除 `backups/`，仍能拉到并显示 2.5 GB。
- **目标**：类目读数来自**同一次拉取的真实条目**；已删除的目录不得再现；整包体积 = 各类目之和（含重叠说明）。
- **判据**：
  1. 删除 `backups/` 后，类目读数与包内清单均不再出现该目录。
  2. 整包字节数与原生同 selection 导出逐字节一致（同源可比时）。
  3. 任何缓存命中必须标「缓存」，且缓存键含 selection + 宿主版本 + 数据快照时间。
- **先读文档**：`host-capabilities.md` §「Luker selection 契约」、`docs/host-pull-performance.md`、`.trellis/spec/guides/tavern-datapack-formats.md`。
- **涉及模块**：`fetchHostBackup()` 的 selection 透传、OPFS 缓存/半成品、`src/core/inspect.js` 类目统计、图表面板类目读数。
- **依赖**：P0-1（同一读数管道）。
- **状态**：BLOCKED（宿主侧，插件不得改用户设置）
  > **用户 2026-11-05 裁定**：只认 Luker **原上游**；任何 fork 仅开发版、不正式使用。插件**严禁更改宿主任何用户设置**，也**禁止自动点注入的「从宿主拉取」**；只打开原生拉取位置并弹窗提示用户自己点。
  > 因此上游 `settings ↔ backups/` 绑死无法由插件绕过：用户勾了 settings，包就会带 backups。
  > 插件侧只做两件事：① 拉取完成后在**插件自己的**选择树里默认取消 `backups/` 与 `user/`；② 如实显示本次包含备份快照的体积。是否要在上游侧拆分，属宿主改造，不在本插件范围。

### P0-3 备份快照 / 原生资产默认必须不勾选

### P0-5 勾选数据包时，点非复选框区域会清空全部选择

- **现象**：点数据包行内其它区域或空白处，导致全部取消选择。
- **目标**：只有显式「反选」按钮或复选框本身能取消；行内其它区域点击不得改变选择。
- **判据**：
  1. 点击行文本、图标、空白处，选择集合不变。

### P0-6 点数据包切换图表有约 0.3 秒延迟

- **现象**：切换数据包后图表明显滞后。
- **目标**：选择变化到图表更新 ≤ 1 帧（16ms）的同步路径；重计算放后台且不阻塞选中反馈。
- **判据**：
  1. 点击到选中态变化 ≤ 50ms（Performance 面板）。
  2. 图表数据在下一帧更新；重扫描不阻塞主线程长任务。
  3. 快速连点不同包，最终图表与最后选中包一致（无竞态）。
- **先读文档**：`state-management.md`、`workbench-three-layer.md` §2（阶段门控）。
- **状态**：DONE（2026-11-05 代码：先 `view.setActivePackage()` 立即切视图，`ensurePlan()` 后台补扫描且仅在仍为当前包时重绘；去掉了点卡后的重复三连渲染；待 Performance 实测）

## 3. P1 · 图表与布局（Luker 原生观感）

### P1-1 图表自适应网格：边贴边、可拖拽、宽屏最多 4 列

> 2026-11-05 修订：上一版「只竖排、绝不并排」是对「所有图表被压成一条并排」bug 的误判。
> 用户明确要求：图表按网格自适应，宽屏最多 4 个并排，每个图表 DOM 边相互贴着。

- **现象**：桌面版图表 DOM 没有下拉框；所有图表挤成一条、并排堆叠；数值不随选项变化。
- **目标**：
  1. 每个图表 DOM 顶部有**格式下拉框**（条形 / 圆环），切换即时重绘。
  2. **自适应网格**：一行放几个由宽度决定，宽屏最多 4 个；不得把所有图表压成单条。
  3. 每个图表 DOM 的边**相互贴着**（无间隙或统一 1px 分隔线），可拖拽改高度/宽度。
  4. 图表 DOM 无空白区域（高度由内容决定，无固定大留白）。
  5. 所有数值随复选框/下拉变化**实时更新**（无缓存陈旧值）。
- **判据**：
  1. 1280px 视口一行最多 4 个；768px 约 2 个；320px 1 个。
  2. 任意两个图表矩形不重叠；相邻边间距 ≤ 1px。
  3. 拖拽后尺寸落库，刷新后保持。
  4. 改变任一类目勾选，图表数值在下一帧变化。
- **先读文档**：`workbench-single-view.md` §1/§3、`ui-orchestration-rules.md` §1（布局铁律）、`component-guidelines.md`。
- **涉及模块**：图表面板渲染、`#chart-stack`、quota/类目统计。
- **状态**：DONE（代码，2026-11-05）——`#chart-card` 设为容器，`.chart-stack` 改 CSS Grid，`@container` 520/800/1060px 分 2/3/4 列；`.chart-group`/`.vol-grid` 用 `display:contents` 让卡片直连网格，`gap:1px` 贴边；`.vol-card{resize:both}`，右下角拖拽按 `data-volkey` 落 `localStorage`；每卡面板头新增 `[data-chartfmt]`（条形/圆环），切换即时重绘；`[data-volchart]` 用同一份类目数据渲染条形或 SVG 圆环。**待浏览器实测列数与拖拽。**
