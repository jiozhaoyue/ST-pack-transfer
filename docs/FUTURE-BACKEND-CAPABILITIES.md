# 需要后端的优秀能力（固定登记 · 供基石插件改造）

> **本文件是需求的固定落点，不是本轮实现清单。**
> 2026-11-09 用户明令：**本插件绝对禁止做后端插件**。凡必须依赖后端才能成立的功能，
> 一律登记在此，连同调研结果与建议做法，供后续「基石插件」改造时决策。
>
> 登记规则：每条写清 **目标 / 为什么必须后端 / 现有宿主能力 / 建议接口 / 验收 / 风险**。

---

## 0. 边界（再次声明）

- 本插件保持纯前端：核心功能在浏览器内闭环，不新增 `plugins/`、不引入 Node 运行时依赖。
- 需要后端的路径在插件内只能**如实标注不支持**，不得假装成功，也不得用「本机中转」冒充零流量。
- 本文件中的建议实现，未经用户对新载体的授权，不得动工。

---

## 1. 服务端直传（源 → WebDAV / S3，不经本机）

### 目标

用户选择「自动备份」后，服务端把数据直接推到 WebDAV/S3，浏览器不承载任何文件字节。

### 为什么必须后端

浏览器发起的任何上传，字节都要经本机网卡到目标端。只有服务端执行体才能让字节
「宿主服务器 → 对象存储」直连。前端无法绕过这一物理事实。

### 现有宿主能力（2026-11-09 取证）

| 宿主 | 服务端插件 | 出站 HTTP | 说明 |
| --- | --- | --- | --- |
| Luker 2.9 | **有**：`plugins/` + `enableServerPlugins: true`，Express Router，路由挂 `/api/plugins/{id}/`，继承宿主鉴权，无沙箱 | Node fetch | 可读 `data/<user>/`、可跑长任务 |
| ST | 无插件机制 | Node fetch | 无扩展后端 |
| TauriTavern | 无（扩展不能 invoke Tauri 命令） | Rust 侧 | 插件不可控 |
| PureTavern | 无插件机制 | 有 | 只有一方模块 |
| Authority（可选） | **有** Jobs / HTTP / KV / Blob 适配层 | 有 | 跨宿主可用的通用执行体 |

### 建议接口（任选其一）

```http
POST /transfer/jobs
{ "source": {"kind":"host-backup","selection":{...}} | {"kind":"path","path":"..."},
  "target": {"kind":"webdav","url":"...","username":"...","secretRef":"..."},
  "chunks": {"size": 8388608},
  "verify": ["sha256"] }
→ { "jobId": "..." }

GET /transfer/jobs/{jobId}
→ { "state":"running|done|failed", "bytes":123, "chunks":{done:12,total:40}, "error":null }
```

- 凭据由服务端保存（`secretRef` 指服务端密钥），前端只传引用，不回传明文。
- 分片与断点由服务端维护；前端只轮询状态。
- 校验：每片 sha256 + 最终清单 sha256。

### 验收

1. 触发后浏览器网络面板零大文件流量，仅有状态轮询。
2. 服务端日志可查源、目标、分片数、校验结果。
3. 断网重试后不重复上传已完成分片。
4. 失败可重试，不产生假成功。

### 风险

- 服务端插件无沙箱，安装即信任；必须由用户显式开启。
- 凭据落在服务端，需要与宿主现有密钥存储对齐，不能明文落盘。
- 宿主升级可能改变插件接口（以官方 `docs/development/server-plugin.md` 为准）。

## 2. 宿主侧通用代理（大文件 / 非 JSON body）

### 目标

浏览器无法直连某些 WebDAV/S3（CORS 或私网）时，经宿主服务端转发。

### 现状（2026-11-09 取证）

- ST / Luker 有 `/proxy/:url(*)`，由 `enableCorsProxy` 控制，**默认关闭**。
- 该中间件把 `PUT/POST/PATCH` 的 body 做 `JSON.stringify(req.body)` ⇒ **二进制/ZIP 会损坏**，
  只能承担小请求（OPTIONS / PROPFIND 文本 / 鉴权探测）。
- TT / PT 无对应端点。

### 建议做法

- 若基石插件提供通用代理，接口应保持**流式透传**（不解析 body、不设 JSON 限制），
  并限制目标白名单、请求体上限与超时。
- 建议接口：`POST /proxy-stream?url=...` + 请求体原样透传，响应流式返回。
- 本插件在探测到该能力前，一律直连并如实报告 `cors-blocked`。

## 3. 服务端定时任务（真正的「自动」备份）

### 目标

按计划（例如每天）在服务端生成并推送备份，不依赖用户打开浏览器。

### 现状

- 纯前端插件只能在页面存活时工作；页面关闭即停止。
- Luker 服务端插件与 Authority Jobs 均可承载定时器。

### 建议接口

复用 §1 的 `POST /transfer/jobs`，增加 `schedule: {cron: "..."}`；
`GET /transfer/jobs?schedule=...` 返回下次运行时间与上次结果。

### 验收

- 关闭浏览器后任务仍按计划执行。
- 每次运行留可查回执，失败可告警（宿主 toast 或日志）。
