# 局域网互传

## Goal

让用户在同一局域网内把数据包直接从一台设备送到另一台设备，不经云盘、不经 U 盘、不经命令行。
纯前端核心用 WebRTC DataChannel，Authority 可用时增强。会话模型＝一次性取件码。

## 参考实现取长补短（2026-10-14 取证）

| 来源 | 借鉴 | 落点 |
| --- | --- | --- |
| Luker（`Instance/Dev/Luker/src/sync/*`、`public/scripts/lan-sync.js`） | 类目勾选（传哪些内容）、传输后按条目数核对、诚实报错（连不上/认证失败分别提示）、相对时间戳 | 取件面板与核对 |
| TauriTavern（`src-tauri/crates/tt-adapter-sync/src/sync/lan/*`） | 阶段+进度的作业事件、能力协商 features、原子落盘（半成品不覆盖目标）、自然续传（按大小+修改时间跳过已完成）、地址发现、二维码配对 | 传输协议与进度 |

**不照搬的**：Luker/TT 都是**本机起 HTTP/HTTPS 服务、对端连过来**（Node / Rust）。
本插件纯前端，**浏览器不能监听端口**，故必须换成 WebRTC DataChannel。这一点已实测通过。

## Requirements

| 编号 | 要求 |
| --- | --- |
| R-01 | 入口：执行区一个按钮「发送到另一台设备」，点开进取件面板 |
| R-02 | 发送端：选包 → 生成取件码 → 等待接入 → 传输 → 完成；全程有进度 |
| R-03 | 接收端：扫码或粘贴取件码 → 建立连接 → 接收 → 落进工作区 |
| R-04 | 取件码一次性：传输完成或超时即失效，不留配对记录 |
| R-05 | 核心信令＝手工交换（二维码承载压缩后的 offer；应答以文本码回传） |
| R-06 | Authority 可用时增强：信令中继，取件码降为短码，单步完成 |
| R-07 | 非安全上下文（`http://<局域网IP>`）下 WebRTC 不可用：明确提示，降级为「导出文件 + 取件码」，不假装能直连 |
| R-08 | 大包分块流式传输，带进度；接收端按块落盘，**半成品不覆盖目标** |
| R-09 | 传输完成后核对：接收端条目数与源端一致才算成功 |
| R-10 | 传输内容可勾选类目（复用内容范围） |
| R-11 | 失败可重试；已收到的块不重传 |
| R-12 | 无外部依赖：不引入 WebRTC 库，直接用浏览器原生 API；不依赖任何 CDN |

## Acceptance Criteria

- [ ] AC-01（R-01）：执行区有「发送到另一台设备」；截图为证
- [ ] AC-02（R-02/R-03/R-05）：两台设备在同一局域网完成一次传输，接收端得到**字节一致**的包
- [ ] AC-03（R-04）：取件码用后失效；再用报错
- [ ] AC-04（R-06）：Authority 可用时短码单步完成；不可用时走手工交换，功能不缺
- [ ] AC-05（R-07）：`http://<局域网IP>` 下明确提示不可直连并给出降级路径
- [ ] AC-06（R-08）：中断后目标文件不被半成品覆盖；重试不重传已收块
- [ ] AC-07（R-09）：条目数不一致时判为失败并提示
- [ ] AC-08（R-12）：无 CDN 引用；`file://` 下不因外部请求失败
- [ ] AC-09：五个守卫全绿；`npm test` 零回归
- [ ] AC-10：交付含真机双设备截图对照

## 已实测的技术前提（2026-10-14，Playwright）

- `file://` 与 `http://localhost` 均为安全上下文；`RTCPeerConnection` / `crypto.subtle` / `navigator.clipboard` 可用
- 无 STUN 时 offer/answer 各带 2 个 mDNS（`.local`）ICE 候选，DataChannel 两端 `connected`，32 KB 消息完整送达
- 单条消息上限受 `maxMessageSize` 限制，大包必须分块

## 待验证风险

1. **跨机 mDNS 解析**：同机已通过；两台不同机器依赖双方浏览器的 mDNS responder，部分网络禁组播时会失败。需真机验证。
2. **SDP 体积 vs 二维码容量**：需实测压缩后 offer 能否装进 QR。装不下则改为「短码 + 文本粘贴」。
3. **纯前端无 Authority 时是两步交换**（二维码去 + 应答码回），不是一步。此限制必须在界面上说清楚，不能伪装成一步。

## 范围外

- 不做账号体系、不做云中转、不做后台常驻服务。
- 不写宿主源码，不要求用户安装 Node 或任何运行时。
- 不复用宿主原生 LAN 同步（那是同步宿主数据，与本插件的数据包语义不同）。
