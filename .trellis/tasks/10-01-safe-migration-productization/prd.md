# 安全迁移产品化：普通用户跨宿主向导与可验证交付

## Goal（目标）

让普通用户在无 AI 指导、无命令行操作的条件下，完成一次可解释、安全的跨宿主迁移，终点是目标内数据可用且得到相应核对，而不是只生成 ZIP。

## Acceptance Criteria（验收标准）

AC-01～AC-14 代表后续产品实现/验收，当前不勾选；AC-15 是本轮已完成并核验的工作流文档交付。

- [ ] AC-01（R-01/02/08）：首次进入默认向导；用户可辨来源、目标、范围、检查、执行与核对；高级入口可达；普通路径不要求命令行或 AI 代操作。
- [ ] AC-02（R-03/05）：新迁移的有效默认选择覆盖全部权限允许且可迁移类目，含设置/密钥/插件；显示每个排除、权限不足与未知项，不能继承旧会话污染值。
- [ ] AC-03（R-04）：源备份、目标包、报告独立可领取且用途不混淆；目标包仍是目标原生布局；报告不泄露密钥或聊天正文。
- [ ] AC-04（R-05/06）：确认绑定当前源、目标、选择与计划版本；更换任一关键输入后原确认失效；源端确认不能授权目标写入。
- [ ] AC-05（R-06）：无自动备份证据且无用户原生备份确认时，目标写请求为零；人工确认与机器验证分别呈现；无法完整预检不显示无冲突。
- [ ] AC-06（R-06）：合并夹具中目标独有文件/空目录保留；同名更新行为与确认一致；宿主源码和工作区穿透链接不成为写入目标。
- [ ] AC-07（R-01/05）：分清格式转换、宿主取数、当前宿主写入、目标核对四种能力；完成报告区分已核对、人工确认、已接受缺项和待核对。
- [ ] AC-08（R-07）：中断或部分失败后，未知写入状态不自动重试；可重试集合仅含有充分证据的安全项；部分成功不会被整体重传。

## 范围外与不变约束

- 不执行旧实例同步任务的真实写入，不清理源实例、历史备份或用户工作区，不重复修复已归档缺陷。
- 不增加跨实例自动直传、同步后台服务、外层迁移套装或新的强制依赖；不修改宿主源码或第三方 vendor。
- 既有高级功能保留；本次普通迁移默认路径不等于授权全量覆盖/删除。
- 宿主差异集中桥接层；复杂宿主 UI 使用官方可支持入口/Popup，设置页仅承载入口与设置；核心无 DOM，模板同源，CSS 作用域与主题继承不变。
- 本插件浏览器缓存不是唯一长期资产事实源；PureTavern 自有 IndexedDB 作为该宿主原生资产库的本项目例外，不等于允许本插件另建事实源。导出文件可由用户持有，但“触发下载”不能当作“已保存且可恢复”的证明；四宿主均须目标写前独立备份。

## 技术验证门（不改变已定产品范围）

用户侧产品决策已经收敛；以下证据工作安排在 S0，未满足前不把对应能力标为已实现：

1. 按官方资料与 Dev 验证列出每种宿主读/写/备份/核对能力。不可自动执行时使用已批准的原生手动引导；不可取得的数据显式列缺项。
2. 核对“默认全选”与有效选择、历史备份、缓存/宿主私有数据、管理员权限的映射；不能套用旧同步脚本的排除策略。
3. 列出能安全重试的操作边界；无法证明可重试的写入一律保持人工核对，不以 UI 承诺替代证据。
4. 明确各长任务阶段的有界等待参数与测量依据，并证明半成品保留路径；不凭空承诺所有宿主能断点恢复。
5. 旧超长规范按主题拆分须另列修改范围并获准；本轮不向超限页追加。现有规范的旧端口、旧例外只作 S0 对账，不混入本次未授权修订。
