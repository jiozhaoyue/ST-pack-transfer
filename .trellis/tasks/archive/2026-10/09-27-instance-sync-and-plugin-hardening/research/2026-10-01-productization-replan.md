## 2. 重新定义“落地”与“人性化”（候选，待裁定）

推荐的产品目标：普通用户不需要 AI 带操作、不需要读源码、也不需要运行运维脚本，
能完成一次安全的数据包迁移或备份，并明确知道结果和剩余限制。

“人性化”不是换配色，而是以下可观察行为：

- 用户先说要做什么，再看必要选项；压缩算法、差量基包等专业参数按需展开。
- 执行前说清来源、目标、包含范围、排除项、敏感内容、是否会写入或覆盖。
- 不让“没有数据”“无权限”“尚未检测”“宿主不支持”显示成同一种禁用按钮。
- 运行中说明正在扫描、下载、转换还是写入；不可计算百分比时不制造假精度。
- 出错后解释哪一步失败、已做什么、没有做什么，以及安全可行的下一步。
- 结束后区分“产物已生成”“下载已触发”“宿主写入已返回”“目标核对完成”。
  浏览器无法证明用户最终把文件保存到哪里，不应声称已安全归档。
- 普通结果页可读，详细技术日志可展开；诊断导出默认不包含密钥与真实聊天正文。

目前仍需用户决定：首要受益者是普通插件用户，还是当前多实例管理员；
本提案推荐前者，但没有把推荐当成已选择。

## 3. 路线比较（均未获实施授权）

| 路线 | 收益 | 代价与风险 |
| --- | --- | --- |
| 只补缺口与文案 | 变更面小，旧同步链较快收口 | 入口与状态解释问题可能保留，持续依赖熟练使用者 |
| **保留核心，按用户任务渐进重构（推荐）** | 复用已验证核心、修复用户流程与维护边界，可分片验收和撤回 | 需要明确流程契约、兼容旧工作区，并先补覆盖关键行为的测试 |
| 全量重写 | 自由度最大 | 四宿主格式、安装形态、断点与恢复语义都须重新证明；目前没有证据支持其净收益 |

重构的准入条件：必须同时写清用户收益、耦合证据、受影响文件、行为保持测试、迁移策略与代码回退点。
源代码回退不等于用户数据回滚；没有可用备份的真实写入不能用“可 git 回退”来包装安全性。

保持的边界：纯前端主路径、可选后端降级、宿主差异集中桥接、核心无 DOM、唯一模板、
本地依赖免用户构建、Dev-only 自动化测试、实例源码禁改与链接禁穿。
本轮不改变技术栈，不安装新框架，不创建第二套转换引擎，不删除旧实现。

## 5. 相应规范候选：要写成可验证契约

以下条目是待评审要求，尚未写入正式 spec。正式新增页每页小于 32768 字节；
按“范围/入口/数据契约/错误矩阵/正反例/测试断言/错误与正确做法”组织。
宿主 API 的事实必须查官方文档；本文不凭阅读宿主源码发明接口。

### N1 用户流程与动作可用性

- 范围：用户开始、配置、预览、执行、查看结果的每一步。
- 入口：沿用 getWorkbenchHtml 和现有动作求值边界，新增组件不得另存一份 selection。
- 契约：页面持续显示当前操作、来源、目标、范围；不可用动作说明原因与可行替代。
- 错误矩阵：未选源→提示选择源；未探测→检查中；不支持→解释限制并提供导出/人工导入路径；
  权限不足→解释所需权限，不冒充网络错误。
- 测试：换包、换目标、载入工作区后，预览与实际执行读取同一份有效配置；隐藏高级区域不改变含义。
- 错误：按钮灰色但无解释。正确：说明当前宿主不能直接恢复，并保留可用的导出路径。

### N2 操作安全与结果真实性

- 范围：任何写入、覆盖、敏感内容导出与多目标搬运。
- 入口：既有 restoreToHost(zipBlob, { mode='merge', platform='st', signal, timeoutMs }) 等边界；
  此处引用现有签名，不授权新增宿主调用。
- 契约：执行前确认目标身份、模式、有效范围、权限条件和备份状态。
  仅源包扫描不能精确知道目标冲突；无法取得目标清单时必须标为“未知/无法完整预检”。
- 错误矩阵：权限不足/明确不支持→不写；用户取消确认→不写；请求中断且服务器可能已写入→状态不确定、先核对，
  禁止自动宣称回滚或盲目重试；部分失败→列已成功、失败、跳过、未核对。
- 测试：确认前零写请求；管理员类内容在权限不满足时不可执行；merge 保留目标独有内容；
  非事务恢复中断后不显示“全部撤销”。
- 错误：HTTP 成功就展示迁移全部完成。正确：分别报告写入返回与可实施的目标核对。

### N3 长任务与断点真实性

- 范围：下载、转换、压缩、恢复；优先复用 TaskManager，不并排创造第二个状态机。
- 契约：工作阶段、进度基准、最近进展和可用操作明确；每个异步阶段有 timeout/destroy/cancel 的 settle 兜底。
  超时阈值及依据须在具体子任务设计中确定，不能把所有阶段粗暴设成同一时间。
- 错误矩阵：短时无进展≠失败；超时→可解释终态；仅部分落盘→不能把内存中的已读条目标成已完成；
  恢复上传取消≠服务端已回滚。
- 测试：暂停后关闭/恢复场景按现有 checkpoint 不变量验证产物内容，而非只断言跳过计数；
  销毁后 promise 能 settle；Worker terminate 后引用失效；进度刷新继续 rAF 合帧。
- 错误：进度 100% 就说目标数据已恢复。正确：下载、转换、上传、核对分别对应真实阶段。

### N4 交付与验收边界

- 范围：Git URL 插件、独立 Web、离线交付声明、四平台能力说明。
- 契约：格式兼容、宿主读、宿主写、外部接口依赖分别列证据；可选增强缺席不阻断基础功能，
  但若会影响用户数据覆盖范围，必须在结果中明确解释，不能借“静默降级”掩盖缺项。
- 错误矩阵：未实现的纯库提供方接口→标注依赖未满足；file:// 仅提示页→不宣称双击即用；
  浏览器缓存→说明缓存性质，不冒充永久备份。
- 测试：离线/no-backend、各支持入口、损坏包、未知格式、配额不足；安装不要求最终用户 npm install/build。
- 错误：一个格式转换用例通过就写“全平台全闭环”。正确：按能力维度逐项兑现承诺。
