# 安全迁移产品化设计（规划评审版）

> 用户已批准保留核心渐进重构；本文件描述目标设计，不是当前实现事实，也不授权编码。
> 总任务负责跨分片约束。具体宿主 API、重试边界和离线打包参数先由 S0/S7 的技术验证确认，再进入对应子任务设计。

## 1. 设计目标与不变量

普通用户从默认向导完成跨宿主搬家；不需要 AI 代操作或命令行。已有高级能力保留，用户完整自用默认全选。
核心不变量：计划/预览/执行/报告同一快照；确认绑定当前操作；写入先有适用备份；未知不是零；结果必须有证据。

规范分工：
- [迁移用户流程](../../spec/frontend/migration-user-journey.md)：统一计划、默认选择、交付角色、向导语义。
- [迁移安全与证据](../../spec/frontend/migration-safety-and-evidence.md)：授权、备份、核对与重试。
- [迁移兼容与验收](../../spec/frontend/migration-compatibility-and-release.md)：旧资料保留、交付关口与验证。

以上相对地址仅为任务工作副本指针；正式规范自身不依赖任务目录。

## 3. 状态与数据流

### 3.1 单一用户意图与计划快照

现有类目选择组件承载用户编辑意图；控制器在关键变更时生成新 revision 的不可变计划。
执行和报告只消费该快照，不再从 DOM 临时重建另一份配置。
向导与高级工作台读取同一意图/计划；只读快照不是第二套可写状态。

向导步骤是显示位置；TaskManager.state 仍是运行真源，MigrationOutcome 只是核对结论。
不得用“显示在第六步”推导执行 done，更不能用 TaskManager.done 推导目标数据已全部核对。

source/target/selection/options 改变 → 新计划 → 原确认失效 → 新预览。
网络/Worker 结果携带所属 revision；过期回调丢弃其 UI 更新，但按原任务生命周期释放资源。

### 3.2 源端

1. 特性检测和包扫描提供能力/范围，不请求未授权管理员数据。
2. 生成完整自用默认计划，展示不能获取/转换的内容及原因；不继承旧同步脚本的排除习惯。
3. 检查页集中展示敏感性与限制，用户确认后调用既有取数/转换链路。
4. 保留可获取范围内原始源备份，生成目标布局包，再形成独立报告。
5. 三个交付项共享逻辑迁移标识但不包入外层套装；数据 Blob/OPFS 引用复用，避免为每个页面重复读入大包。
6. 原始宿主备份与可选聊天库补齐的覆盖范围分别核算；不能反推“目标包补齐了聊天，所以原始备份也完整”。

无法生成合规源备份时不伪造一个“完整备份”标签；先解释可获取范围和限制，必要时停留在检查页。

### 3.3 文件中转与目标端

普通用户手动下载并选择目标包，不要求两端在线直连，不需要共享浏览器数据库。
目标端独立识别 ZIP；可选报告仅辅助解释，不带来可信授权。没有报告时只就目标包可证明的范围给结论。

目标流程：目标身份 → 包与格式核实 → 合并/未知冲突说明 → 自动或原生手动备份 → 本地确认 → 写入 → 核对。
不支持插件写入的宿主，走有证据的原生手动导入指引；不编造跨宿主统一恢复端点。
只要目标、身份、内容范围变化，旧确认与重试资格都失效。

### 3.4 核对与安全恢复

写入返回、目标核对、人工声明分别记录。按每类数据的真实单位和能力核对，不将 ZIP 条目数等同于角色/聊天数。
可自动全量核对的范围留相应证据；只能抽样或人工确认的部分明确标注方法和范围。
失败后先汇总已应用/未应用/未知，再计算安全重试候选。未知和不可拆分部分操作不盲目重放。

## 4. 存储与旧版本兼容

- 不清 files/OPFS；保存新会话前保留可回读的旧 active_session 记录，利用既有 workspace 的 key 结构，不预先决定升 DB_VERSION。
- 旧会话快照保留文件引用，不复制大 Blob；新保存失败不覆盖旧记录。
- TaskManager 的断点持久化仍走注入 adapter；核心不感知 Authority，也不依赖浏览器全局对象。
- 旧任务缺少新字段时走只读恢复/安全重开；未知版本不尝试“猜着续跑”。
- 浏览器存储只是可清理缓存：稳定交付仍是用户持有的文件或宿主原生保存，不承诺清缓存后可找回。

## 5. UI 与可访问性约束

默认向导按来源、目标、范围、检查、执行、核对逐步呈现；高级参数按需展开。
主步骤只有清楚的主要动作，后退不丢选择；不支持/无数据/未检测/无权限分别解释。
正在执行时显示实际阶段和最近进展，无法准确计算百分比时使用不定进度，不给假剩余时间。
支持键盘操作、合理焦点返回、移动端无关键操作遮挡；这些是新 UI 的验收要求，不声称现状已经通过真人测试。
宿主内复杂 UI 放官方 Popup 等支持位置，设置页保留入口和偏好；桥接层处理差异，样式继续双前缀和主题变量。

## 6. 渐进切换与回退

1. 先锁住现有计划、产物和断点行为的特征测试。
2. 抽离纯判定，不改变旧按钮行为；用同输入比较结果。
3. 让旧动作也调用统一控制器，再接入向导，避免两个执行者同时存在。
4. 默认入口切换前完成旧工作区兼容和目标安全门负例。
5. 代码回退只撤销新片的装配/路由，不删除用户新产物或旧工作区。

不引入一整套长期保留的“新旧双实现”；临时切换接缝仅用于分片验证，稳定后另审是否清理。
每次提交/推送未来仍遵守显式 pathspec、暂存区集合核对与 origin 纪律；本轮没有提交授权。

## 7. 风险与固定降级

| 风险 | 固定处理，不悄悄变更用户目标 |
| --- | --- |
| 宿主无法列出目标内容 | 显示未知冲突；不伪造预检精确度 |
| 无自动备份能力 | 原生备份+明确人工确认；无条件则不自动写入 |
| 无法证明重复写安全 | 不自动重试，给人工核对路径 |
| 纯库提供方接口缺失 | 列覆盖不足，不把磁盘空目录当作聊天总量为零 |
| 原始包/产物过大 | 优先流式与引用复用，预算由测量确定；不暗中截断数据 |
| 规范注入过长 | 本次三页保持单页小于 32768 字节；旧长页独立列修订范围 |
| file:// Worker/module 不可用 | 后续 S7 单独验证构建；此前不宣传双击即用 |

## 8. 进入实现前的技术验证

S0 产出版本化能力矩阵、范围映射和重试安全操作清单；无法取得证据的能力明确走已批准降级。
任何新技术栈、强制后端、新依赖、删除/覆盖用户资料或扩大实例写入范围，都必须回到用户决策，不由本设计隐式授权。
