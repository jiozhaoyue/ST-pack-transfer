## 一、用户裁定

1. 扩展「数据包转运」在宿主里加载失败（`Failed to fetch dynamically imported module`），必须**完全修复**。
2. 扩展管理要与**原生管理扩展完全联动、功能覆盖**，例如管理员可把扩展在
   「管理员/全局扩展」与「仅用户扩展」之间移动。
3. 探明**扩展加载顺序**是什么，是否可以手动调整。
4. 删除**无包空态**里的「导出宿主扩展列表」按钮。
5. 继续 Trellis 台账。

## 二、根因与证据（R1）

- 宿主：Luker 桌面版 `https://127.0.0.1:8060`；`/scripts/extensions/third-party/*`
  映射到 `%APPDATA%\Luker\data\default-user\extensions\` 的 git clone（**不经打包器**）。
- 事故代码：`src/ui/workbench-view.js` 的
  `import demoExtensionsData from '../data/demo-extensions.json'`。
- 浏览器不支持无导入属性的 JSON 模块静态导入 ⇒ 整张依赖图实例化失败 ⇒ 宿主统一报
  `Failed to fetch dynamically imported module`。Vite 开发/打包会转换 JSON，所以独立态正常。
- 取证：对扩展 80 个模块逐个 HTTP 拉取，全部 200；唯一非 JS 模块就是该 JSON。

## 三、实现

### 3.1 修复加载（R1）

- 新增 `src/data/demo-extensions.js`（ESM 数据模块），删除 `src/data/demo-extensions.json`；
  `workbench-view.js` 改导入 `.js`。
- 新增**入库守卫**：`tooling/no-bundler-only.js` + `npm run check:no-bundler-only`，拦截
  JSON 静态导入 / `node:` 静态导入 / 裸包名 / Vite 专有语法（`?raw`、`import.meta.env` 等）。
  函数体内的动态 `import('node:fs/promises')` 刻意放行（仅 Node 测试路径）。

### 3.2 作用域互转与安装到全局（R2/R3）

- `src/ui/host-bridge.js` 新增 `moveExtensionViaHost(name, source, destination)`
  → `POST /api/extensions/move`，body `{ extensionName, source, destination }`，
  `source/destination` 取 `global|local`；**双向都要求管理员**；204 成功 / 403 / 404 / 409。
  带 CSRF、120s 超时、原文截断与失败原因码。
- `index.js` 暴露 `actions.moveExtension`。
- `workbench-view.js`：`moveScopeWithConfirm()` / `moveInstalledExtension()`；
  行内按钮**仅管理员渲染**；成功后清空列表缓存并重拉。
- 管理员判据：`readHostIdentity().admin === true`；宿主页进入即 `loadServerPlugins()`，
  不再依赖「先去开发者页」。
- 安装到全局：`installExtensionViaHost({global})`、`installExtensionBatch()` 透传 `entry.global`；
  安装区复选框仅在管理员时渲染，默认仍是用户作用域。

### 3.3 加载顺序（R4，只读结论）

- `manifest.json` 的 `loading_order`（数字，越小越早）；缺失等价 0，同值按 `display_name`。
- SillyTavern：升序后**逐个 `await` 串行激活**；
  Luker：同一升序，**同值组内并行、组间串行**（`public/scripts/extensions.js` 的
  `activateExtensions()` 注释即证据）。
- 原生 UI 只按它**排序显示**，没有编辑入口；宿主也**没有写回 manifest 的端点**。
- 因此“手动调整”= 改扩展自己的 `manifest.json` 后刷新（全局扩展需管理员/文件权限）。
- 本插件：`manifestToExtension()` 保留 `loadingOrder`，列表显示 `#N`，排序新增「加载顺序」，
  **不提供伪编辑**。

### 3.4 删除空态按钮（R5）

- 删除 `#btn-assetlist-host`、其事件分支与 `empty.assetListBtn/Hint` 两个 i18n 键。
- 导出清单入口保留两处：图表卡 `[data-assetlist]`、扩展管理宿主页工具条
  `#extmgr-export-assetlist`。

## 五、未实机取证 / 已知边界

- **作用域互转与安装到全局尚未在真实宿主点过按钮**：端点、权限、状态码已核对 ST / Luker 上游源码；
  需在 Dev 实例做一次实机取证。
- 加载顺序不可在插件内修改（宿主无写端点）。
- 原生「启用 / 禁用」开关未纳入：它写宿主 `extension_settings.disabledExtensions`，
  没有独立端点；整包保存设置会覆盖宿主状态，故不做。
- 用户当前那份 Luker 桌面克隆仍停留在旧提交：需在原生扩展管理里点「更新/删除重装」后刷新
  （本插件自己加载不出来时，不能依赖它自己的更新按钮）。
