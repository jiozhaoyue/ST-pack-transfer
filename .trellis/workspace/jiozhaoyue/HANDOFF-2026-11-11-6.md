# 交接 · 2026-11-11 第六轮（Session 82）：逐扩展自动更新 / 批量更新卸载 / 清单统一入口 / Git 常显 / 教程居中

## 一、本轮用户裁定（原话整理）

1. **自动更新放回宿主已装扩展**：只在每条扩展上设置；可设**短至 5 秒**轮询；模式仍是「仅提醒 / 直接更新」。
2. **批量管理**：已装扩展列表内可批量更新、批量卸载。
3. **数据包恢复的扩展清单**不再有独立界面，统一到「宿主 → 安装扩展」，可控制安装 / 更新 / 指定版本分支。
4. **Git 可视化看不到** → 入口改为**常显**（不再用开关藏）。
5. 数据包面板 `?` 只剩空圆 → 补回 `?` 字符。
6. **所有教程居中**显示在浮层里。
7. 体检默认字体大小并调整。

## 二、实现

### 2.1 逐扩展自动更新

- `settings-panel.js`：删除 `devMode` / `gitAutoUpdate` / `gitUpdateIntervalHours` / `gitUpdateMode` /
  `gitUpdateSelected` / `gitAutoUpdateLastAt`；新增 `gitAutoUpdateRules`（`{name:{mode,intervalSec,url?,global?}}`）。
  `normalizeUpdateInterval()` 夹在 **5–86400 秒**；`normalizeUpdateRules()` 兼容旧模型一次性迁移。
- `workbench-view.js`：宿主页每行「关闭 / 仅提醒 / 直接更新」+ 秒级间隔（`min=5`）；
  `saveUpdateRule()` / `resolveUpdateRepo()`（优先登记仓库，其次宿主 `.git` 的 `remoteUrl`）/
  `scheduleAutoUpdates()` / `runAutoUpdateTick()`（`setTimeout` 循环，最小 5 秒，演示模式不跑）。
- 开发者页只剩账号 / 存储位置 / OAuth / 令牌指引。

### 2.2 列表内批量管理

- 每行：复选框、更新、卸载；列表头：全选 / 反选 / 取消 / 批量更新 / 批量卸载 / 指定版本分支输入。
- 更新：有远端地址走 `installExtensions(... replace:true)`；否则 `POST /api/extensions/update`
  （`host-bridge.js` 新增 `updateExtensionViaHost()`）。
- 卸载：`POST /api/extensions/delete`；逐条与批量都要二次确认。

### 2.3 扩展清单统一入口

- `host-bridge.js` 新增 `setExtensionManifestSink()`；`maybeOpenExtensionInstaller()` 不再调用
  `renderExtensionInstallerModal()`，改为把 entries 交给 sink。
- `index.js` 注册 sink → `view.openExtensionManager(entries)`（宿主页底部安装区，可填分支 / 版本）。

### 2.4 Git 常显 / 教程居中 / `?` / 字号

- `sideTabAllowed()` 恒为 `true`，`#zone-side-tabs` 常显；`renderZoneSide()` 不再强制回数据包。
- `centerTutorialCard()` 改为 `left/top:50% + translate(-50%,-50%)`；高亮环仍按锚点定位。
- 数据包面板帮助按钮补回 `?`（模板）。
- 字号体检：`#app` 基准 14px 不变；扩展列表 / 说明 / 教程正文抬到 11.5–12.5px。

## 四、未实机取证 / 已知边界

- 宿主 `/api/extensions/update` 与 `.git` 的 `remoteUrl` 真实响应未在 Dev Luker 上跑过；
  目前只按端点契约与本地模拟验证。
- 5 秒轮询在真实站点会受 API 限流影响；失败会静默跳过（不伪造结果），但没有退避策略。
- 批量更新逐条串行（避免并发写宿主），大量扩展时耗时会线性增长。
- 拖拽排序在手机宽度下的可用性未实机验证。
