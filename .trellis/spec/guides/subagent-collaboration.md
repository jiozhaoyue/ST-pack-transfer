# 子代理协作规范（Subagent Collaboration）

> **适用范围**：本项目（及沿用本规范的其他仓）内，主代理需要拆分并行工作时。
> **规则层级**：MUST。违反即视为流程违规。

---

## G-1 来源唯一性：只准用"本 agent 自身的子代理功能" (MUST)

**规则**：派发子代理时，**只能使用当前 agent 平台自带的子代理能力**。

| 平台 | 允许 | 禁止 |
| --- | --- | --- |
| VS Code Copilot | `runSubagent` 工具 | 任何外部 agent 通道 |
| 通用表述 | "本 agent 自身的子代理功能" | "其他 agent" |

**明确禁止的"其他 agent"**（不限于此列表）：

- `trellis channel spawn` 派生的 claude / codex worker（外部 CLI 进程）
- `trellis channel run` 一次性外部 worker
- `pebrel agent delegate` / `pebrel pane send` 交给分屏里的其他 agent
- 手工拉起的外部 CLI agent：`claude`、`codex`、`gemini` 等
- 其他 IDE / 终端 / 浏览器里的 agent 会话

**原因**：跨 agent 通道不受本主代理控制——模型路由不透明、权限与写盘边界不可控、退出与清理无保证。
2026-09-23 实测：`trellis channel spawn` 派出的 worker 使用外部 CLI 进程，主代理无法保证其只读约束，用户随即要求全部终止。

**违反后果**：不可控进程在仓库内写文件、模型路由与成本失控、任务状态出现第二真相源。

---

## G-2 并行不阻塞：一次性并发派发，主代理同轮推进自身工作 (MUST)

**规则**：需要多个子代理时——

1. **在工具调用层一次性并发派发**：同一轮内并行发起多个子代理调用，不得一个接一个串行发起。
2. **主代理同轮并行推进自身工作**：同一轮里同时发起自己的检索 / 读取 / grep / 落盘等调用，与子代理并行执行。
3. **不得空等、不得轮询、不得排队**：禁止"派一个→等它回来→再派下一个"，也禁止 `wait` / 轮询式等待子代理。

**原因**：串行派发把并行工作退化为串行，主代理算力被浪费；用户明确要求（2026-09-23）"主代理不能被子代理阻塞，必须和多子代理同时并行运行"。

**违反后果**：任务耗时线性膨胀；主代理在等待期无所作为；长任务易被对话压缩打断。

---

## G-3 任务自包含 (MUST)

**规则**：每个子代理的提示必须自带以下四项，**不得假设它继承了主对话**：

1. **范围** — 具体文件路径 / 目录 / 模块，不写"看看相关代码"。
2. **问题** — 要回答的具体问题清单（可核查、可证伪）。
3. **期望输出** — 报告结构、必填字段（如 `file:line` 锚点、严重度、证据）。
4. **落盘路径** — 唯一允许写入的文件路径。

**违反后果**：子代理自由发挥 → 产出无法与主代理结论对齐，返工。

---

## G-4 写权限边界：禁止主代理与子代理写同一文件 (MUST)

**规则**：

- 子代理**默认只读**；需要落盘时，只写各自独占的产出文件。
- **同一文件同一时间只能有一个写者**。主代理写汇总/索引文件，子代理写各自分片文件。
- 子代理**禁止修改产品代码**（除非该子代理任务本身就是实现任务，且主代理明确划定了它独占的文件集）。

**违反后果**：并发写互相覆盖，且 diff 无法审出谁覆盖了谁。

---

## G-5 冲突与不可用时的回退 (SHOULD)

**规则**：若子代理能力不可用（平台不支持、额度耗尽、调用失败）：

- 不降级到"其他 agent"通道（违反 G-1）。
- 由主代理**自行串行完成**，并在任务 `implement.md` 记录降级原因。

**原因**：来源唯一性是硬约束，优先级高于并行度目标。

---

## G-6 免费模型可用时必须多开交叉验证，尤其 UI (MUST，2026-11-17 用户明令)

**规则**：只要运行时能提供**实时确认 cost 输入/输出均为 0** 的免费模型，就**必须多开子代理做交叉验证**，不得由主代理单线判读后直接下结论。

| 场景 | 要求 |
| --- | --- |
| **UI / 截图判读** | **强制多开**：≥2 个子代理分头读同一组分块图，独立出结论；不一致列差异由主代理仲裁 |
| 规范 / 文档审查 | 至少 1 个独立子代理复核措辞与规则一致性 |
| 布局 / CSS 修复 | 1 个子代理查根因、1 个子代理查回归面，结论交叉 |

**前置硬约束（与统一规则 G-30 一致）**：

1. 派发前**实时查询模型注册表**，确认所选模型 `cost.input=0` 且 `cost.output=0`。
2. 无法实时确认 cost 为 0 时，**不得声称用了免费模型**，也不得据此跳过或伪装交叉验证；按 G-5 回退并如实记录。
3. 子代理模型一律用免费档（如平台提供 `lite`/free 档）；禁止误用付费模型。

**交叉验证判据**：

- 每个子代理任务自包含（G-3），**只读**同一组证据、落各自独占文件（G-4），禁止改产品代码。

---

## G-7 身份分立与红队交叉找茬（MUST，2026-11-18 用户明令）

**规则**：
1. **身份必须严格分立**：派发子代理时必须具备差异化角色（如审计调研员、方案实施员、专职红队找茬质检员），禁止单一人格或单一视角下结论。
2. **专职找茬与测试质检（Red Team）**：每次涉及界面改动、架构调整或批量导入导出，必须配备至少 1 个红队角色专门挑刺——审查极端小屏溢出、全局样式污染、内存泄露与超时挂起、以及对其他代理提出的方案进行破坏性审查。
3. **主代理职责边界**：主代理专职全局调配、中枢仲裁以及多模态（分块截图）视觉兜底验证，非必要不直接下场修改具体细节代码。
4. **UI 文案短小原则（禁止长名按钮）**：严守 G-16 规范，按钮文案绝对禁止出现复合长句或长名（如禁止“清单转 Git 拉取打包”，必须精简为“拉取清单”等 4 字以内极简文案），补充解释必须收敛至 tooltip/title 气泡中。

- 结论分「一致 / 分歧」两类：一致项直接采信；分歧项必须列出双方锚点（`file:line` 或图块坐标），主代理逐条仲裁后定稿。
- UI 判读必须遵循 `frontend/ui-verification.md` V-7~V-10 的**分块截图 + 精细识别**流程，禁止整图一眼定论。

**原因**：主代理连续误判（把按钮竖排看成正常、把空白误判成浮层压住）证明单线判读不可靠；免费模型边际成本为 0 时，多开交叉验证几乎没有代价，却显著降低误判率。

---

## G-8 主代理职责收窄：只兜底，不亲自下场写细节 (MUST，2026-11-19 用户明令)

**规则**：主代理**只做四件事**——

1. **全局调配与仲裁**（派发、汇总、分歧定稿）；
2. **进度勘察**（实时勘察各子代理进度与产出）；
3. **多模态兜底检查**（分块截图视觉复核）；
4. **兜底实现**（**仅当子代理不可用时**，按 G-5 回退）。

**非必要不直接下场写细节代码**。确需亲自下场时，必须在任务记录里写明原因（与 G-10 降级记录一致）。

**原因**：用户 2026-11-19 明令「必须是子代理主要并发干活，主代理不阻塞，只做兜底和实时勘察进度，还有检查，多模态检查」。主代理陷进细节会把兜底与仲裁职能丢掉。

**违反后果**：并行退化为「主角单干 + 子代理摆设」，主代理算力浪费在细节上，进度勘察与多模态兜底失守，长任务易被压缩打断。

---

## G-9 蜂群并发：一轮并发派发，主代理同轮推进，禁串行禁轮询 (MUST，2026-11-19 用户明令)

**规则**：同一轮内**一次并发派发多个子代理**（工具调用层并行发起），主代理**同轮推进自身工作**。禁止「派一个→等它回来→再派下一个」的串行，禁止 `wait` / 轮询式等待。此为 **G-2 的强化**：目标是「蜂群」——多角色同时干活，而非单子代理接力。

**原因**：用户 2026-11-19 明令「全面子代理蜂群分角色……必须是子代理主要并发干活，主代理不阻塞」。

**违反后果**：蜂群退化为串行，任务耗时线性膨胀，主代理在等待期空转，用户明确禁止的阻塞发生。

---

## G-10 角色优先顺序：内置 → 仓内专用 → 主代理亲自 (MUST，2026-11-19 用户明令)

**规则**：派发时按三级顺序选角色，不得跳级——

| 优先级 | 角色来源 | 例子 |
| --- | --- | --- |
| ① 首选 | 平台**内置**角色 | `scout` / `Explore` / `general-purpose` / `verify-*` / `documents:visual-judge` |
| ② 次选 | **仓内专用**角色（内置不满足时） | `.zcode/agents/*.md`（如 `repo-cartographer` / `pack-forensics` / `host-probe` / `ui-multimodal-judge`） |
| ③ 兜底 | **主代理亲自做**（前两者都不满足时） | 须在任务记录写明**降级原因** |

**原因**：用户 2026-11-19 明令「尽量先用 zcode 内置角色，后续逐渐写我们仓的专用角色」。内置角色免费、通用、已被验证；重复造专用角色会造成角色碎片化。

**违反后果**：重复造轮子、角色泛滥难维护、无法追溯为何主代理亲自下场、免费内置能力被闲置。

---

## G-11 角色持久化：专用角色统一入库、随时可调用 (MUST，2026-11-19 用户明令)

**规则**：仓内专用角色**统一放 `.zcode/agents/*.md`**，纳入 git 跟踪，随时可调用；**不得**散落在临时目录（`tmp/`、`review-shots/`、会话缓存等）。每个角色须写明 frontmatter（`name` / `description` / `tools`）与适用范围、禁止事项、输出格式、与其它角色的边界。

**原因**：用户 2026-11-19 明令「后续逐渐写我们仓的专用角色，持久化，随时调用」。临时目录里的角色会随清理丢失、无法复用、团队无法共享。

**违反后果**：角色资产流失、复用性归零、每次重新造角色、协作失去一致性。

---

## G-12 写权限分立：每个角色独占产出文件 (MUST；G-4 细化)

**规则**：每个子代理（含仓内专用角色）**独占自己的产出文件**；禁止两个角色、或角色与主代理**写同一文件**。只读角色按最小权限只给 `Read` / `Glob` / `Grep` / `Bash`，不得授予写工具。此为 **G-4 的细化**。

**原因**：并发下若多个写者指向同一文件，会互相覆盖且 diff 无法审出谁改了什么；最小权限可防止只读角色越界改代码。

**违反后果**：产出被并发覆盖、证据丢失、审计链断裂、只读角色误改产品代码。

---

## G-13 免费模型：派发前实时确认，不能确认则如实记录 (MUST，2026-11-19 用户明令；G-6 强化)

**规则**：子代理**一律用 `cost.input=0` 且 `cost.output=0` 的免费档**；**派发前实时查询模型注册表确认**。无法确认 cost 为 0 时，必须**如实记录「未使用免费模型」**，不得声称用了免费模型，并按 G-5 回退。此为 **G-6 的强化**，与统一规则 G-30 一致。

**原因**：用户 2026-11-19 明令「子代理一律用免费档」；免费档边际成本为 0，可支撑蜂群多开与交叉验证。

**违反后果**：误用付费模型致成本失控；或以「免费」虚假背书掩盖实际回退，误导后续判断与成本统计。

---

## 检查清单（派发前自检）

- [ ] 用的是本 agent 自带的子代理工具？（不是 `trellis channel spawn` / pebrel / 外部 CLI）
- [ ] 多个子代理在同一轮内**并发**发起？（不是 for 循环里逐个 await）
- [ ] 主代理同轮也发起了自己的工作调用？
- [ ] 每个子代理任务都写全了 范围 / 问题 / 输出 / 落盘路径？
- [ ] 没有两个写者指向同一文件？
- [ ] 子代理不会被要求改产品代码？（除非专项实现任务）
- [ ] 【G-6】已实时确认所用模型 cost 输入/输出均为 0？不能确认则未声称免费、已按 G-5 回退？
- [ ] 【G-6】UI 任务已多开 ≥2 子代理分头判读同一组分块图，且遵循 V-7~V-10？
