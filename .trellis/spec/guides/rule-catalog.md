## 一、三条不可协商

### R-01 出声

任何工具调用，同一轮回复内必须有可读文本：正在做什么、看到什么、下一步。

写规则 / harness / 配置文件前，先文字报备**绝对路径 + 改动内容 + 原因**；写完立刻汇报实际 diff，并读回校验（grep 到标记）。宁可不动手，也不静默动手。

`校验：pointer-consistency（部分）｜其余人工`

### R-02 不可逆操作先问

删除或覆盖已有文件、安装依赖、大范围重构、技术选型、方向性取舍，以及"不确定该怎么做"——一律用交互问答工具给出 ≥2 个结构化选项 + 推荐，等用户选定。禁止在正文里提问后结束回合。

`校验：人工`

### R-03 只改该改的

改现有文件用块级 Edit；禁止整文件 Write 覆盖；禁止用 shell 重定向、`node -e`、`echo` 写源码 / 配置 / 数据。

变更结论必须来自 diff 工具，不靠通读全文。

`校验：人工 + git diff 审阅`

## 二、收尾定义（历史上最反复的失误）

### R-04 做完才算完

禁止以"部分完成"收尾。声称完成前必须同时满足五项：

1. 计划文件中未完成项为 0；
2. `npm test` 全绿；
3. 文档同步（见 R-11）；
4. 已提交并推送 origin（见 R-12）；
5. 已留 mini-trellis 交接记录。

任一项不满足，必须明说"未完成 + 卡点 + 下一步"，不得包装成完成，不得只报"已实现"而不给验证结果。

`校验：plan-open-items`

### R-05 数值必须真实

界面与文档中的体积、条数、进度、配额，一律取自真实读数。

禁止估算、禁止 `~` 前缀、禁止占位假数。读不到就显示"未提供"。教程 / 演示数据也必须是合理真值，并随版本更新。

`校验：no-estimated-numbers`

## 三、边界（写错东西代价最高）

### R-06 实例边界

宿主实例目录内分三类处置：运行时数据可读写；被 git 跟踪的宿主源码严禁改动；指向工作区仓的 junction / symlink 严禁写穿。

实例更新只走 git 或宿主原生安装器。

`校验：人工（写前必须报批）`

### R-07 交付落点

规范与校验器必须落在被 git 跟踪的位置：`rule-catalog.md`、`tooling/**`、`test/**`、`.trellis/spec/**`。

`scripts/`、`.private/`、`e2e/`、`fixtures/` 被 `.gitignore` 忽略——放这里的产物**不算交付**，换机器即失效。

`校验：deliverable-tracked`

### R-08 零泄露

提交前确认：无本地绝对路径、无凭据令牌、无真实聊天数据。

第三方凭据（S3 / WebDAV / Git）只存本机浏览器，默认不写入服务端配置。

`校验：no-secret-leak`

## 四、流程门

### R-09 计划先行

多项改动先落盘计划文件（PLAN / PRD），验收标准不得为 `TBD`；执行中实时勾选，禁止事后凭记忆批量补勾。

`校验：plan-open-items`

### R-10 检索先行

实现前先查现成方案，双通道都试过才算：

1. `WebSearch` / `WebFetch`；
2. GitHub API（`api.github.com/search/repositories`）。

无命中同样放行。

`校验：人工`

### R-11 文档先行 + 同提交

改代码前先读 `docs/DEVELOPER-GUIDE.md` 与 `.trellis/spec/`，不许靠读源码猜功能。

功能 / 行为变更必须在**同一次提交**内同步 `docs/` 与 `README.md`——只改代码视为未完成。

`校验：docs-sync`

### R-12 Git 纪律

`git add <显式路径>`，禁止 `-A` / `-u` / `git add .`。

提交前 `git diff --staged --name-only` 必须恰等于本次清单，出现计划外文件立即中止。完成即推 origin，禁推 upstream。仓库脚本内不得出现 `git add -A`。

`校验：no-git-add-all`

## 五、产品与 UI 硬约束

### R-13 美观优先于塞下

任何屏幕都不得为塞下内容而压缩、截断、压成单条。

空间不足时隐藏次要文案（如"插件"二字），保证功能按钮全显示。

`校验：人工 + 截图`

### R-14 不得重复入口

同一动作只允许一个入口。同一页面出现两个"生成导出包"之类的按钮即为缺陷。

`校验：人工 + 截图`

### R-15 图表布局

1 个占满图表区；2 个均分；3 个四宫格并留空一格。

图与图之间有可拖拽分隔条，紧贴、无空白。宽屏最多 4 列，禁止压成单条。

`校验：人工 + 截图`

### R-16 全屏语义

全屏是"进入另一个视图"（参照宿主原生全屏），不是就地内联展开。

`校验：人工`

### R-17 宿主 UI 只认官方落点

设置页只承载设置项；复杂交互走官方 Popup；消息旁内容挂 RENDERED 事件。

不在官方文档记载的位置，就是禁止的位置。

`校验：dom-injection`

### R-18 CSS 双前缀

注入宿主的每条规则必须带本扩展前缀；禁用 `*` / `body` / `:root` / 裸宿主类；配色一律 `var(--SmartTheme*, 回退值)`，禁硬编码颜色。

`校验：css-scope`

### R-19 数据正确性

读数、体积、勾选状态必须同源、实时、可复核。

身份 / 能力探测失败不得永久降级——失败后必须可重试。

`校验：人工`

## 六、实现约束

### R-20 纯前端优先

主路径必须纯浏览器闭环可用。服务端只作可选增强，走"适配器 + 特性检测 + 静默降级"，核心层不感知后端存在。

`校验：人工（架构审阅）`

### R-21 有界等待与生命周期

任何 `await`（媒体事件、跨源 fetch、渲染 / 挂载 promise）必须能 settle，不得永久 pending。

`worker.terminate()` 后必须把引用置 `null`。高频进度回调必须 rAF 合帧。

`校验：人工（单测覆盖）`

### R-22 单一模板源 + 多入口同改

HTML 只有 `src/ui/workbench-template.js` 一个来源，`index.html` 只许骨架。

同一 UI 的多份副本必须在同一次提交内一并修改。

`校验：template-source`

### R-23 依赖自包含

装完即用，不得要求用户执行 `npm install` / `npm run build`。

第三方库以本地副本放 `src/vendor/`，勿升级改动。

`校验：vendor-untouched`

### R-24 测试与端口

发版前 `npm test` 全绿、零回归；E2E 只对 Dev 实例运行；禁止高内存 / 大规模测试。

端口：`8000` 禁用；`8001–8004` 实例独占；`3000` 系统保留；本地 dev / preview / 静态服务统一 `3040`；周边工具自 `3010` 起。

`校验：port-policy`

## 七、性能与体验（旧规则完全缺失的一类）

### R-25 性能预算

交互反馈不超过约 100ms；本地部署从宿主拉取不超过 10s；任何操作不得慢于宿主原生（实测曾慢 20 倍）。

教程浮层与插件首屏必须即时，不得"操作几次后才出现"。

`校验：perf-budget`

### R-26 宿主原生优先

动手前先盘点宿主**原生已提供**的能力：拉取 / 上传 / 下载 / 扩展管理 / 存储页 / 通知通道。

原生已实现的不在插件内重造；UI 形态、图标、通知通道直接对齐宿主；与原生并发时宿主优先，插件不抢占。

`校验：host-native-first`

### R-27 全平台一致

web / 手机 / 竖屏三种形态下：功能按钮必须全部显示、不得压缩；配额与占用在所有平台都能读到且同源；读数 UI 与交互逻辑跨平台一致。

标签只用一种语言，不写"中文（English）"。

`校验：人工 + 截图`

### R-28 教程模式隔离

教程模式与正常模式互不影响：教程用占位数据演示，不得污染正常模式任何状态；模式切换须有取消/保存。

占位数据必须合理，并随插件版本更新。教程必须讲清操作前提：先勾选才能操作，先生成导出包才能在导出区上传下载。

`校验：人工 + 截图`

## 八、交付与反馈

### R-29 安装来源唯一

同一作者/仓库只允许存在一个安装 URL；支持 `/tree/<branch>` 形式与指定 commit 安装。

私有仓库须在安装前或失败时显式提示"含私有，需登录"。扩展打包支持只选中所选项（本体全量）。禁止本地链接，一律 remote link。

`校验：人工`

### R-30 失败不静默

任何耗时操作必须有可见进度与明确结果，不得只剩空面板或暗遮罩。

失败不得让整体中断：必须保存进度、输出完整报告，并让用户选择丢弃或保留部分成果。

提示必须可持久化（默认每次提醒）。宿主不支持的能力如实说明，禁止返回假空清单。

`校验：人工 + 现有 UI 守卫`

## 十、指针协议（防堆砌的机制）

**唯一真源**：本文件 `rule-catalog.md`（30 条判据）+ `rule-details.md`（细则）+ `iron-rules.md`（注入铁律）+ `rule-triggers.md`（触发索引）。

**其余文件只准放指针**，格式固定为三行：

```md
<!-- RULES-POINTER v1 -->
本仓工程规则唯一真源位于 `.trellis/spec/guides/`：`rule-catalog.md`（30 条判据）、`rule-details.md`（细则）、`iron-rules.md`（会话注入铁律）、`rule-triggers.md`（触发索引）。动手前先读，收尾前跑 `npm run verify:rules`（用法见 rule-catalog.md）。
本文件只放指针、不复述真源条文；冲突以真源为准。
```

适用文件：`AGENTS.md`（顶部）、`CLAUDE.md`（顶部）、`GEMINI.md`、`.github/copilot-instructions.md`、`.cursor/rules/*.mdc`。

**防堆砌三条硬约束**

1. **条数上限 30**。新增一条必须同时给出「校验 ID」或写明「人工 + 理由」。超过 30 条必须先合并或废弃旧条，不得追加。
2. **禁止复制**。任何规则条文只准存在于本文件。其它文件出现逐字重复段落，`pointer-consistency` 直接失败。
3. **案例不进规则**。事故案例与历史叙事写入 `.trellis/spec/guides/details/` 或 `.trellis/research/`；本文件只保留规则与一句判据。
