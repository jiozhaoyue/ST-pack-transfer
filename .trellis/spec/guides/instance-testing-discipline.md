# 实例测试纪律（2026-10-27 定稿）

> 本文件是**硬规则**，不是建议。违反过的事实与代价写在每条后面。

## 1. 并发上限：**任何时刻最多 2 个实例在线**

- 默认只起 **1 个**被测宿主；只有做「两两互传」时才允许**同时 2 个**。
- 需要覆盖 3 个及以上宿主时，**错峰**：跑完一个 → 停掉 → 再起下一个。
- 禁止一次性启动 4/6 个实例。`scripts/restart-instances.cjs` 会一次性拉起全部
  Dev+Real 六个；**测试场景不要用它**，改用：
  ```bash
  node scripts/run-e2e-instances.cjs --only dev-st
  ```
- 实测代价：六实例同时在线 + Playwright 叠加会让 dev-luker 偶发挂载失败、单测超时（flake 根源）。

## 2. 只准 Dev，禁止 Real

- 端口白名单：`8001`(Dev ST) / `8003`(Dev Luker) / `8899`(Dev PT) / `9223`(TT CDP)。
- Real 端口 `8002` / `8004` / `8900` **任何自动化都不得连接**。
- `e2e/lib/guard.cjs` 已有端口守卫，不要绕过。

## 3. 禁止宿主自动拉起浏览器

- Dev ST / Dev Luker 的 `config.yaml`（gitignored，运行时数据）必须保持：
  ```yaml
  browserLaunch:
    enabled: false
  ```
- 禁止与其他「自动开浏览器」的工具/扩展同时运行——会互相抢占标签页，用户会看到
  ST/Luker 自己开新标签（2026-10-27 实测）。
- 启动实例用 `spawn` 后台进程即可，**不要在脚本里再 `start <url>` / `explorer`**。
- 测试收尾必须停掉本次启动的实例；不允许把宿主留在后台过夜。

## 4. PT / TT 的特殊约束

- PT 前端体量大，**headless 下渲染进程 Target crashed**（2026-10-15 两次实测）。
  需要自动化 PT 时必须 headed，故 **PT 测试必须单独跑**，不得与其它实例并行。
- TT 是桌面应用，CDP 探针会占用一个窗口；同样**单独跑**。

## 5. 违规的判定与补救

- 发现「同时 >2 个实例在线」：立即停掉多余实例（`taskkill /PID <pid> /T /F`），再继续。
- 发现「浏览器被自动打开」：先核对 `browserLaunch.enabled`，再核对是否有其它自动开浏览器的
  工具在跑；两者都排除后再怀疑测试脚本。
